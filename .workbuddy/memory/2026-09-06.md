## WidgetIcon 改用 SVG 资源方案（Path 全部失败）

- 用户反馈：坐标预缩放后大小依然没变化。
- 结论：Path 组件在卡片渲染管线三种方案全部不生效——`.width/.height`（坐标绝对映射）、`.scale()`（变换被忽略）、坐标预缩放（用户实测无变化）。Path 在卡片里不可控。
- 换用 SVG 资源方案：13 个 Material Icons 标准 SVG 放 `resources/base/media/`（ic_play/ic_pause/ic_prev/ic_next/ic_heart/ic_heart_fill/ic_shuffle/ic_repeat/ic_repeat_1/ic_list/ic_music/ic_crown/ic_refresh），WidgetIcon.ets 全部换成 `Image($r('app.media.xxx')).width(size).height(size).fillColor(color)`。
- 空心 heart 改用 Material `favorite_border` 的填充式轮廓路径（偶奇填充规则），避免 stroke 在 SVG 里的不确定性。
- SVG 里 fill 写 #FFFFFF 占位，Image 的 `.fillColor()` 覆盖着色。
- 构建验证通过：`assembleHap BUILD SUCCESSFUL in 6s`。

## 列表封面不显示（根因修复）

- 根因：正在播放封面走 prefetchCover 转 data:base64 塞进 FormBindingData（零网络请求），列表封面只拼网络 URL 下发。FormExtensionAbility 渲染进程对 Image 加载网络 URL 不可靠（官方文档原话"部分场景可能存在加载失败"），已实测全部不显示。
- 修复：列表封面也走 dataImage 路径——新增 resolveCoverToDataImage(cover)，用 getImageUrl(cover, 96) 走 optimize 代理下载转 data:base64，5 条列表 +10-15KB 远低于 FormBindingData 限制。syncPlaylists/syncHistory/syncLatest 的封面、syncHistory 的 nowPlaying.cover、EntryFormAbility.restoreNowPlayingFromPersistedState 的封面全部统一走这条路径。writeAndPushNowPlaying 同步把封面 dataImage 存 widget_now_playing_cover_cache 供冷启动恢复用。
- 构建验证通过：`assembleHap BUILD SUCCESSFUL in 6s`。

## 列表封面 file:// 方案（dataImage 失败后的最终方案）

- 用户反馈 dataImage 方案仍然不显示。根因两层：① resolveCoverToDataImage 里外链封面直接 return http URL（Subsonic/Emby 的封面在卡片进程加载不了）；② dataImage 走 FormBindingData 有截断风险。
- 最终方案：主 App 下载 → 写 filesDir/widget_covers/ 本地文件 → 推 file:// 路径给卡片。文件大小不受 FormBindingData 限制，卡片 Image 读本地文件可靠。
- 改动：resolveCoverToDataImage → resolveCoverToFile（下载 → writeCoverToDisk → file://），外链封面也统一下载；新增 dataImageToFile（data:base64 → 本地文件）；EntryFormAbility.restoreNowPlayingFromPersistedState 用 resolveCoverForRestore 统一处理（cached dataImage → file://，裸 URL 手动拼）。
- 构建验证通过：`assembleHap BUILD SUCCESSFUL in 6s`。
