- mobile 取不到色的原因：连接的 NAS 服务端是旧代码无此接口（404/错误信封 → null 回退默认色），部署新版即恢复，**不是客户端 bug**。
- 本地验证：nest start 会清空 dist（206 文件）被 safe-delete 钩子拦截；改用 `NODE_PATH=. npx ts-node -P tsconfig.build.json --transpile-only src/main.ts`（NODE_PATH=. 解决 `src/services/...` 运行时解析）。
- 结果：`/image/dominant-color?src=/covers/001.mp3.jpeg` → {"r":115,"g":59,"b":50}，二次 15ms（磁盘缓存命中）；非法 src 返回 HTTP200+信封 code:404（**该 API 异常走全局信封、HTTP 恒 200**，客户端不能只靠 res.ok，必须校验 r/g/b 是 number——mobile/hm 实现均已做）。
- desktop 不走服务端：canvas 本地取色（CORS 失败回退主题色）。

## mobile/hm 播放页背景补高斯模糊层
- 用户实测：取色成功但没有模糊+渐变效果（原来只做了渐变罩层；且旧版渐变 Svg 只靠 style absoluteFill 没显式 width/height props，大概率没渲染）。
- 修复：mobile 用 expo-image（blurRadius=70 + scale 1.2 防边缘露底，对齐 desktop blur(80px)）打底 + Svg 渐变罩层加显式 width/height="100%"；hm 用 ArkUI Image .blur(70).scale(1.2) + linearGradient 罩层（angle 70 ≈ CSS 160deg）。
- 两端结构统一为：模糊封面层 + 主题色渐变罩层（插件定义背景时整体不渲染）。
