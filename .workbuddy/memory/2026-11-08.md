## mobile 冷启动恢复两连修：有声书自动播放 + 音乐 mini 播放器消失
- 症状：清后台重进，音乐模式 mini 播放器不展示；有声书能恢复但会自动播放；音乐→有声书切换也自动播放。
- 根因 1（自动播放）：PlayerContext 的 PlaybackState「切歌/连播兜底」（~963-979）——状态停在 Ready/Stopped 且 currentTrack 存在、userPausedRef=false（冷启动默认值）就 TrackPlayer.play()。loadPlaybackState 重建队列后 RNTP 停在 Ready，恰好命中 → 冷启动/模式切换恢复即出声。
- 修复 1：新增 `suppressAutoResumeRef`（初始 true）；loadPlaybackState 入口置 true（恢复只重建队列/进度，绝不出声）；仅 playTrack/playTrackList/resume 三个显式播放入口清除；兜底 if 整体加 `!suppressAutoResumeRef.current` 闸门（含 isManualSwitchPending 臂，显式播放会先清标记所以不受影响）。
- 根因 2（音乐消失，高置信）：savePlaybackState 整列持久化原始 Track（含 lyrics 长文本 + likedByUsers/listenedByUsers/playlists 嵌套数组）。音乐队列常是整个曲库（数百上千首），JSON 可达数 MB 超 AsyncStorage（Android 默认 6MB）→ 写入永远失败且 catch 只打日志 → playbackState_MUSIC 一直缺失 → 冷启动走 else 分支清空 → mini 播放器不展示。有声书队列仅单专辑几十集，体积小所以正常。
- 修复 2：savePlaybackState 持久化前瘦身（剥离 lyrics/嵌套数组，仅当前曲目保留歌词）+ 队列窗口裁剪（当前曲前后各 50 首，PERSIST_TRACK_WINDOW=50）+ 写入失败降级保存单曲目最小状态（保底 mini 播放器可恢复）。
- 顺带修竞态：PlayModeProvider 的 contentMode 是 AsyncStorage 异步加载，旧逻辑初始恢复只等 isSetup/isAuthLoading，若持久化模式是 AUDIOBOOK 会先按默认 MUSIC 恢复一轮（建音乐队列+Ready 事件）再切换二次恢复，两次 setQueue 并发交错。修复：playMode.tsx 暴露 `modeLoaded`，PlayerContext 初始恢复 effect 加 `!modeLoaded` 闸门（deps 同步加）。
- 已知取舍：恢复队列被窗口化（±50 首），非当前曲目无歌词（当前曲目保留）；恢复后不再自动播放，需用户手动点播放（产品预期行为）。
- 验证：mobile tsc 改动文件 0 错误（全量仍有既有错误）；Android `expo export` 通过（9.28MB bundle）。注意 expo/react-native CLI 必须在 apps/mobile 目录内跑（root 没有 bin）。
- 待真机验证：①音乐模式杀后台重进 mini 播放器恢复且不自动播放；②有声书同理；③音乐→有声书切换不自动播放。

## hm 桌面小部件 VIP 误锁修复（widget_vip 脏缓存 + plus token 冷启动缺失）
- 根因链：① EntryAbility.initialize 从不恢复 plus token（setPlusAuthToken 只有各页面懒加载才调）→ 冷启动 refreshAll→syncVip 调 /vip/status 无 Authorization → 服务端 401 missing token → 缓存永不更新；② EntryFormAbility.readIsLocked 对 updatedAt>0 的 widget_vip 缓存无限信任 → 一旦缓存过 isVip=false 永久误锁；③ 登录/支付/内测开通 VIP 后无任何点位触发 widget VIP 重同步。App 内正常是因为各页面调 plusApi 前都自己 setPlusAuthToken。
- 修复：
  - EntryAbility.initialize：authStore.loadFromStorage 后从 kvStore 读 plus_token 并 setPlusAuthToken。
  - WidgetBridge：syncVip 改 public；isVip 翻转时 scheduleSyncNowPlaying 立即推卡片（updateForms 带 isLocked）；新增 clearVipSnapshot（删 widget_vip + 推卡片）供 plus 退出/注销调用。
  - EntryFormAbility.readIsLocked：缓存说「非会员」时不再盲信，卡片进程实时复核 plusApi.getVipStatus（成功顺带刷新缓存），网络失败才回退信任缓存；缓存说 VIP 直接放行。
  - 会话内联动：MemberLoginPage 登录成功、MemberPaymentSuccessPage 支付刷新、SettingsPage 内测开通 → syncVip()；MemberDetail/MemberBenefits 退出登录、SettingsPage 注销会员 → clearVipSnapshot()。
  - 顺手修 SettingsPage.confirmDeleteMemberAccount 笔误：删的是 plus_userId（不存在的 key），改为同时删 plus_user_id。
- 验证：hvigorw assembleHap BUILD SUCCESSFUL；harmony-cleanup.sh 已跑。

### 补充：真因是接口口径不一致（实机日志定位）
- 装机重启后日志显示 syncVip 已能跑通（token 修复生效）但 `isVip=false changed=false` → 服务端 /vip/status 对该账号就是 false，而 App 内皇冠/会员页用 /users/me 的 vipTier 判定显示会员。

## mobile 底部栏在播放页进出场不再隐藏（2026-11-08）
- 需求：播放详情页关闭动画期间 tab+mini 播放器消失、结束后才从底部滑入 → 改为底部栏始终在原位置，播放页只是从它上方滑过。
- 方案（apps/mobile/app/_layout.tsx）：`showBottomBar = !hideBottomBar || rootSegment === "player"` 播放页期间保持挂载；`bottomBarLayerBelow = rootSegment==="player" || barRestorePending` 时传 `layerBelow`（zIndex -1 压到 native Stack 下层）；同时 `contentStyle.backgroundColor` 在该窗口期设 transparent，让底层页面 padding 条带透出下层的底部栏（底层页面自身根容器有 colors.background，不受影响）。
- barRestorePending 语义从「延迟重新挂载」改为「退场动画期间维持 layerBelow」，仍由 transitionEnd 精确解除 + 1.5s 兜底；GlobalBottomBar 的 animateIn 滑入动画不再使用（组件内保留未删，便于回退）。
- 关键前提：JS 浮层 zIndex 无法稳定压住 RNScreens 转场页面（Android 尤其），所以方向只能是「栏压下层 + padding 条带透明」，不能「栏在上层等播放页盖住」。
