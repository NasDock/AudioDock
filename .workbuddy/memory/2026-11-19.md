## 追加：问题 2 真根因 —— 与数据源无关，是云端部署的 WS 路径前缀被剥掉
- **用户反馈**：修完平台通道后仍不生效，且「我明明不是飞牛源，这功能跟数据源无关」—— 用户是对的。
- **排查实锤**（读 Tauri webview localStorage + 实测云端）：
  - AudioDock 云端地址是 `https://cloud.audiodock.cn/mmdctjj/ad`（**按租户路径挂载**），HTTP API 走该前缀正常（GET /user/devices code=200）。
  - `normalizeSocketUrl()` 把路径**整个剥掉** → socket.io 连根路径 `/socket.io` → 网关返回 `{"error":"User not found"}` → 所有端 WS 永远注册不上 → 设备表全离线 → 任何源下「在线设备」都空。
  - 实测：根路径探测被拒；`/mmdctjj/ad/socket.io/?transport=polling` 握手正常。
- **第二个坑**：云端网关**不支持 WebSocket 直连 upgrade**（socket.io-client `transports:["websocket"]` 15s 超时；带 upgrade 头 curl 秒回 400 = upgrade 头被网关剥掉）。polling 起手（再升级）则正常。
- **修复（packages/ws/src/index.ts，dist 已重建）**：
  1. 新增 `resolveSocketEndpoint()`：无路径→默认 `/socket.io`；`/api`（自建 nginx 约定）→根路径；其他前缀（如 `/mmdctjj/ad`）→ `path: <前缀>/socket.io`。connect 签名含 path。
  2. `transports: ["websocket"]` → `["polling", "websocket"]`（polling 起手再升级，升级失败则停留 polling，功能完整）。
  3. 修了自己引入的正则分组 bug（`m[1]` 只捕获到协议名 → url 变 "https"）：分组改为 `^((?:wss?|https?):\/\/[^\/?#]+)(\/[^?#]*)?`。
- **端到端验证（真实云端，用户账号）**：dist 构建版 SharedSocketService 连 `https://cloud.audiodock.cn/mmdctjj/ad` → 连接成功、`GET /user/devices` 显示测试设备 isOnline=true。连接前云端 8 台设备全部 isOnline=false（印证全端列表为空）。
- **遗留**：
  - harmony 的 HarmonySocketService 是 ohos 原生 WebSocket（只能 transport=websocket 直连）→ **云端网关下无法连接**（需网关开启 upgrade 代理，或在 harmony 实现 engine.io polling，工作量大）。harmony 的 buildUrl 保留路径前缀，本身无路径 bug。
  - 云端设备表留有两条离线测试设备（`ws_pathfix_probe01`/`ws_dist_probe01`，「WS-路径修复验证」「WS-dist构建验证」），服务端无设备删除 API，无法清理。
  - services 的 `TransferSessionPayload.targetPlatform` 放宽为 `string | null`（mobile player.tsx 传 null）。
- **教训**：① 排查先看用户实际部署形态（云端按租户路径挂载是独有约定）；② Bash 工具每次调用都重置 CWD 到 workspace 根，所有命令必须显式 `cd` 或用绝对路径（本次被坑 4 次）；③ father build 清理 dist 会被沙箱 safe-delete 拦截，需先手动 `rm -rf dist`。
