## 修复：mobile 访问令牌页路由跳首页 + 匿名元数据写入漏洞
- **mobile 跳首页根因**：`app/_layout.tsx` 有两张路由白名单，新增页面必须同时登记（对照 webdav-sources 提交 7737bac5 的三处改法）：
  1. `isDetailPage`（isLoading 后鉴权重定向用）：`token && !inAuthGroup && !isDetailPage → router.replace("/(tabs)")`——未登记的路由会被强制弹回首页；
  2. `hideBottomBar`（全屏页隐藏底栏）；
  3. `Stack.Screen` 注册。
  上次只加了 3，本次补上 1、2（`segmentName/rootSegment === "access-tokens"`）。
- **「停用 token 不生效」排查结论**：停用机制本身正常（3001 实测：禁用后 guarded 接口 401「访问令牌无效或已停用」，PUT/DELETE /track/:id 一直受 guard 保护）。真正漏洞是**元数据写入接口 `POST /track`、`POST /artist` 历史上是 @Public**，匿名即可写，令牌启停管不到。已移除这两个 @Public（artist.ts 的 Public import 一并清理；app 端无人调用 createTrack/createArtist，仅 native adapter 有死代码）。
- **保持 @Public 不动的接口（有意为之）**：`GET /track/stream/:id`、`/track/:id/playback-qualities`、`/image/optimize`、`/image/dominant-color`、`/hello`、scan-login 会话接口——小程序 BackgroundAudioManager/微信 `<image>` 无自定义 header 能力，媒体与封面必须免鉴权；静态挂载 `/covers/`、`/music/`、`/audio/` 走 Express 层不经 Nest guard，同样公开。
- 验证：3001 实例 A~H 全场景 curl 通过（匿名写 401、有效令牌/JWT 放行到 controller、停用后 401、stream 保持 Public）；api build、mobile tsc 过。测试 token 即建即删，实例已停。
