# 2026-10-17

## mobile 横屏封面轮播卡顿修复（CoverFlow）

修复 `apps/mobile/app/player.tsx` 手机横屏堆叠式封面轮播滑动/切换卡顿问题。根因不在 JS 动画层（此前已修 memo/动画节点稳定/缩略图档位/prefetch），而在渲染层：

1. **iOS 图层阴影离屏渲染（主因）**：`coverFlowItem` 原样式同时有 `shadowOpacity + borderRadius` 且无 shadowPath → 滑动时 5 个封面每帧重算阴影 → 掉帧。修复：移除 layer shadow，改为两层静态深色扩散 View 假阴影（`coverFlowShadowOuter/Inner`，仅 iOS 渲染），Android 靠 elevation 原生阴影。
2. **Android zIndex/elevation 冲突**：原同时给 `zIndex` 和 `elevation: 8`，Android 上 elevation 全等 → 旁侧封面按 add order 盖住中心封面。修复：按平台分支——iOS 用 zIndex，Android 用动态 `elevation: 30 - |basePos| * 6`（中心最高）。
3. **Android Image fadeDuration=300ms**：新滑入封面"慢慢显形"，快速切换感知为卡顿。修复：`fadeDuration={0}`（prefetch 已兜底）。

`player.tsx` tsc --noEmit 无本次相关报错（现存报错均为历史遗留：artist/[id]、member-benefits、webdav-sources、SkeletonBlock、networkUtils）。

经验：RN 里带圆角的 layer shadow（shadowOpacity<1 无 shadowPath）在 transform 动画下是 iOS 掉帧经典源，动画值再干净也救不了渲染层，要么上 shadowPath/boxShadow，要么用静态假阴影层。

## mobile 横屏封面轮播「堆叠」对齐 hm（第二、三轮）

**第二轮（改错，已回退）**：误把 hm 的 `coverFlowZIndex = 100 - round(|effPos|*10)` 当作真机行为，给 mobile 加了 lead boost 半程穿插——错误方向。

**第三轮（用户最终判定，正确方向）**：hm 真机实际的堆叠顺序是 **1-2-3-4-5（从左到右递增，越靠右层级越高、盖住左侧）**，不是 1-2-3-2-1（中心最高）。原因：ArkUI Stack 默认「后书写的子组件覆盖先书写的」，ForEach 按 `cur-2..cur+2` 书写，书写顺序即最终层叠；`coverFlowZIndex` 公式在真机上被这个默认顺序盖过（未按公式生效）。mobile 修复：`zOrder = 10 + basePos`（iOS zIndex / Android elevation，∈[8..12]，低于中心播放按钮 zIndex 110），尺寸/间距不动；递增体系天然自带穿插行为（左滑下一首在右高位盖当前、右滑上一首在左低位被盖），无需 boost。lead state/props/reset 整套已删除，`tsc` 无报错。

**教训（跨端对齐类需求的通用做法）**：不要用“读对岸代码推导语义”当结论——hm 代码公式和真机实际行为不一致（zIndex 公式 vs Stack 默认顺序）就是实例。用户说“看看 hm 端实现”时，除了读代码，优先确认对岸**真机实际呈现**，让用户一句话判定期望方向，再动手。

ArkUI 已查证事实（后续跨端对齐别再猜）：
1. **ArkUI Stack 的 alignContent 默认是 `Alignment.Center`**（官方文档 ts-container-stack-V5，非官方博客写的 TopStart 是错的）——hm 封面以容器中心为基准锚定，translate 0 即居中。
2. **ArkUI Stack 子组件按书写顺序层叠、后写的覆盖先写的**（官方文档原话 "successively stacked and the latter one overwrites the previous one"）；zIndex 可覆盖书写顺序，但在 hm 封面场景实际呈现仍为书写顺序 1-2-3-4-5。
3. **ArkUI 多 transform 属性按声明顺序依次应用**（scale→rotate→translate，位移是绝对视觉量，不被前面 scale 缩放），与 RN `transform: [{translateX}, {scale}]`（T·S 矩阵，视觉位移=tx）语义等价——两端锚点数值 0/77.8/133.3、scale 1/2/3 一致。

另（第一轮卡顿修复，保留结论）：mobile 横屏封面轮播滑动卡顿根因是 iOS layer shadow 每帧离屏重绘，已改静态假阴影层；Android fadeDuration=300ms 已关。
