# 2026-10-17

## mobile 横屏封面轮播卡顿修复（CoverFlow）

修复 `apps/mobile/app/player.tsx` 手机横屏堆叠式封面轮播滑动/切换卡顿问题。根因不在 JS 动画层（此前已修 memo/动画节点稳定/缩略图档位/prefetch），而在渲染层：

1. **iOS 图层阴影离屏渲染（主因）**：`coverFlowItem` 原样式同时有 `shadowOpacity + borderRadius` 且无 shadowPath → 滑动时 5 个封面每帧重算阴影 → 掉帧。修复：移除 layer shadow，改为两层静态深色扩散 View 假阴影（`coverFlowShadowOuter/Inner`，仅 iOS 渲染），Android 靠 elevation 原生阴影。
2. **Android zIndex/elevation 冲突**：原同时给 `zIndex` 和 `elevation: 8`，Android 上 elevation 全等 → 旁侧封面按 add order 盖住中心封面。修复：按平台分支——iOS 用 zIndex，Android 用动态 `elevation: 30 - |basePos| * 6`（中心最高）。
3. **Android Image fadeDuration=300ms**：新滑入封面"慢慢显形"，快速切换感知为卡顿。修复：`fadeDuration={0}`（prefetch 已兜底）。

`player.tsx` tsc --noEmit 无本次相关报错（现存报错均为历史遗留：artist/[id]、member-benefits、webdav-sources、SkeletonBlock、networkUtils）。

经验：RN 里带圆角的 layer shadow（shadowOpacity<1 无 shadowPath）在 transform 动画下是 iOS 掉帧经典源，动画值再干净也救不了渲染层，要么上 shadowPath/boxShadow，要么用静态假阴影层。

## mobile 横屏封面轮播「堆叠」对齐 hm（第二轮）

用户反馈 mobile 横屏封面堆叠不对，对照 `apps/harmony/.../pages/PlayerPage.ets` 后发现唯一结构性差异在层级语义：

- **hm `coverFlowZIndex = 100 - round(|effPos|*10)`，effPos 含 panX 小数** → 拖过半程后目标封面 zIndex 连续反超当前封面（半程穿插穿插通过）。
- **mobile 原来 `zIndex = 100 - |basePos|*10`（整数档）** → 拖动全程旁侧永远压在當前封面下，滑到半程两封面并排时穿插关系错误 = 用户说的"堆叠不对"。

修复：RN 的 Animated 驱动不了 zIndex，用整数 `coverFlowLead`（-1/0/+1，由 `onPanResponderMove` 里 `|panX| >= step/2` 判定）+ 子项层级 boost（iOS zIndex +15 / Android elevation +10，均保持 < 中心播放按钮 zIndex 110）近似复刻；snap/rebound 完成、外部切歌 effect 里 reset。`tsc --noEmit` 对 player.tsx 无报错。

顺带：假阴影层从 iOS-only 改为双端渲染——Android elevation 投影需要 outline，coverFlowItem 无背景色实际画不出投影，hm 的 ArkUI shadow 则一直有，双端假阴影对齐投影视觉。

ArkUI 两个已查证事实（后续跨端对齐别再猜）：
1. **ArkUI Stack 的 alignContent 默认是 `Alignment.Center`**（官方文档 ts-container-stack-V5），不是 TopStart（非官方博客写错）——hm 封面以容器中心为基准锚定，translate 0 即居中。
2. **ArkUI 多 transform 属性按声明顺序依次应用**（scale→rotate→translate，位移是绝对视觉量，不被前面的 scale 缩放），与 RN `transform: [{translateX}, {scale}]`（T·S 矩阵，位移=tx）语义等价——两端锚点数值 0/77.8/133.3、scale 1/2/3 一致，纯数值抄不齐的话必然是层级/语义问题。
