## 缓冲进度条（三段式）可行性分析（仅分析未实现）

- 结论：四端引擎全部原生支持取缓存进度，纯前端改动。

## 缓冲进度条两端对齐修复（Slider 轨道 inset 问题）

- **根因**：部分 Slider 组件的轨道两端会内缩「半个滑块宽」（滑块始终完整处于轨道内），自绘的底轨/缓存层若铺满全宽，两端就会露出没被播放进度盖住的区域（hm 表现为开头一小段空的）。
- **逐端核实结论**（读源码/组件行为）：
  - hm ArkUI Slider：轨道 inset = blockSize/2 → 修复：Slider 显式 `blockSize({width:16,height:16})` + `trackThickness(4)`，自定义层外套一层 `padding({left:8,right:8})` 的 Stack 对齐（PlayerPage + EmbeddedPlayerPanel）。
  - mini 微信 Slider：同样 inset = blockSize/2（12px → 6px）→ 修复：自定义层外套 `.player-slider-trackbox`（left/right 12rpx），缓存层 % 宽度相对内缩后的轨道区才精确。
  - mobile miblanchard slider：读 lib/index.js 确认最小轨 left=0、宽 = ratio*(W-thumbW)+thumbW/2，从 x=0 开始 → 无此问题。
  - desktop antd Slider：rail 铺满全宽、无 inset → 无此问题。
- 经验：给 Slider 叠自绘层时，先确认该组件轨道是否有半滑块 inset；有就必须同步内缩，且 inset 数值要由显式 blockSize 锁死。
