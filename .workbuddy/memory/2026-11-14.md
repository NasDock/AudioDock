## mobile 歌词页：手动拖动接管 + 中心行选时播放（手机/Pad/横屏）

需求（原始是全端，本次只做 mobile）：手动滚歌词时自动跟随不能把位置抢回去；拖到中心的行左侧显示时间戳、右侧播放按钮，点了从该行 seek 并播放；2s 内没点就回到当前正在播放的歌词行；**暂停/停止播放时拖动也要能回弹**。

### 架构变更
- 新增 `apps/mobile/src/components/LyricsScrollArea.tsx`：把原先散在 `app/player.tsx` 里的 `AnimatedLyricLine`、两个歌词 ScrollView、自动滚动 effect 全部收敛成**一个共用组件**。横屏右栏 / 竖屏全屏 / 车机分栏（CarMode 横屏走竖屏 JSX）都调它，避免多套逻辑行为不一致。
- `player.tsx` 净删 287 行：删掉 `scrollViewRef` / `currentLyricIndex` / `lyricContainerHeight` / `lineLayouts` / 自动滚动 effect / 两处重复歌词 JSX / 6 个已无引用的歌词样式；`parseLyrics` 保留（`LyricsFontSizeModal` 仍从 `app/player` import），新增顶层 `parsedLyrics = useMemo(...)` 和 `renderLyricsArea(withBackgroundPress)`。
- 只有竖屏传 `onBackgroundPress`（点歌词空白区切回封面）；横屏不传。

### 关键实现点（容易踩坑）
- **行 layout.y 的坐标系**：上下半屏留白必须放在**行容器自身**（`linesWrapper` 的 paddingTop/Bottom = H/2），不能放 `contentContainerStyle`。放 contentContainer 时 wrapper 自身 y=H/2，行 onLayout.y 相对 wrapper 从 0 起，会少掉 H/2 偏移 → 中心行判定和回弹整体错半屏。现在 `layout.y` 天然等于内容坐标，可直接和 `contentOffset.y + H/2` 比较。
- **回弹不能依赖 position 变化**：2s 定时器里显式 `scrollTo(当前播放行)`；暂停时 position 不变、effect 不会重跑，只有这条显式路径能回弹（需求最后一条）。
- 自动跟随用 `autoScrollKeyRef = trackId|index|fontSize|round(H)` 节流，替换原 effect 里恒真的 `activeIndex !== currentLyricIndex || lyricFontSize`（数字 truthy → 每次 position 变化都 scrollTo）。
- 行 onLayout 的 y 变化（H/字号改变）用 rAF 合并后重新定位，防止节流键把测量前的错误位置锁死；首帧 layout 未就绪由 80ms×5 重试兜底。
- 接管标记用 ref（`interactingRef`）供手势回调/effect 闸门同步读，state 只驱动操作条显隐；`onScrollBeginDrag` 接管并清 timer，`onScrollEndDrag` + `onMomentumScrollEnd` 起 2s 倒计时；程序化 scrollTo 不触发 drag 事件，且 `scheduleIdleReset` 有 `if (!interactingRef.current) return` 双保险。
- 中心操作条 `absoluteFillObject + justifyContent:center`，高度 `max(52, fontSize*2+12)`、宽度 `maxWidth:560` → 手机窄屏 / Pad 宽屏 / 横屏半栏 / 车机分栏都自适应，无硬编码尺寸。
- 接管期间屏蔽竖屏「点歌词切回封面」，避免误触；`pointerEvents="box-none"` 让浮层不挡滚动手势，只有播放按钮吃点击。
- 点播放：`seekTo(line.time)` + 未播放时 `resume()`，并立即 `scrollToIndex(index)`；`isPlaying` / `position` 用 ref 快照供异步回调读最新值。

## desktop / hm / mini 三端补齐同一套歌词交互（同日第二轮，已提交）

需求：把 mobile 的「手动拖动接管 + 中心行时间戳/播放按钮 + 2s 回弹（暂停也生效）」移植到其余三端。四端语义统一，**回弹一律由定时器显式 scroll，不依赖播放进度变化**。

| 端 | 主改动 | 滚动/中心行方案 |
|---|---|---|
| desktop | `components/Player/Lyrics.tsx`（重写交互）+ `index.module.less`（wrapper + 操作条）+ `Player/index.tsx` / `CarMode/index.tsx`（注入 `onSeekPlay` / `trackId`，4 个渲染点） | 原生 div `onScroll` 统一接管（滚轮/触屏/滚动条全覆盖）+ `getBoundingClientRect` 实测中心行；`autoScrollingRef` + `scrollend` 精确区分程序化滚动；`scrollIntoView` 换算沿用原公式 |
| mini | `pages/player/index.tsx`（原地增强）+ `index.scss` | `ScrollView` + `scrollIntoView`/`scrollIntoViewAlignment='center'`（同值不触发 → 先清空再 30ms 设回）；`createSelectorQuery` 实测行 y/height，失败时按 rpx 估算兜底；无 `onLayout`/命令式 scrollTo |
| hm | `PlayerPage.ets`（竖屏+横屏共用 lyricsView）与 `EmbeddedPlayerPanel.ets`（车机 9:16 面板） | `List.onScrollIndex(start,end,center)` 的 `center` 直接给中心行，零测量；`onTouch(TouchType.Down)` 接管、`onScrollStop` 起 2s；`subscribe` 自动跟随加 `!lyricInteractingRef` 闸门；`Stack` 兄弟层 + `hitTestBehavior(None)` |

### 三端关键坑（下次别再踩）
- **desktop**：`Lyrics.tsx` 原有 `autoScrollingRef` 只用于滚动条显隐，不会阻止自动滚动 effect 抢位置 → 必须加接管闸门；`scrollend` 监听的 effect 依赖要带 `parsedLyrics.length`（歌词异步解析，首次挂载走「无歌词」占位分支，容器还不存在，空依赖会永远注册不上）；CarMode 父层 `onClick={cycleMergedView}` 会在拖动时误切视图 → wrapper 接管期间 `stopPropagation`，播放按钮自己也要 stopPropagation。
- **mini**：`scroll-into-view` 是「值变化才触发」的受控属性；小程序没有 RN 的 `onLayout`/`scrollTo`，所以中心行用实测 + 估算双路径；**不要加全宽覆盖层**做操作条（小程序 `pointer-events` 行为不一致会挡住滚动手势）→ 拆成时间 badge / 播放按钮 / 两条 1rpx 细线独立绝对定位。父层 `onClick` 退出歌词需要 `lyricSeekPlayAt` 时间戳兜底（小程序 `stopPropagation` 不是所有基础库都可靠）。
- **hm**：**LRCParser 的 `time` 是毫秒**（mobile 是秒）→ `playerStore.seek(line.time)` 直接传，时间显示才 /1000；ArkTS 里带参 @Builder 是按值快照，接管状态必须独立 `@State`（不能塞进 `view` 快照）；`List.onScrollIndex` 的 `center` 在程序化滚动时也会回调，必须用 `lyricInteractingRef` 屏蔽；`hitTestBehavior(HitTestMode.None)` 只禁自身、子播放按钮仍可点。
- 三端统一：切歌复位接管状态、卸载清 timer、点播放 = seek + 未播放时 resume/play。
