## 小部件封面全部不显示（真凶：mkdirSync EEXIST）

- 现象：上新单曲 / 歌单 / 历史 / 正在播放 的封面全是占位音符，且「偶尔能显示一次」。
- 排查方式：**hdc 抓 hilog 是唯一有效手段**（App 日志 domain 是 `com.audiodock.app/AudioDock`，`Logger` 输出形如 `[WidgetBridge] xxx`）。
  ```bash
  HDC=/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/hdc
  $HDC shell "aa start -b com.audiodock.app -a EntryAbility"
  $HDC shell "hilog > /data/local/tmp/hl.txt & sleep 14; kill %1; grep -E 'com.audiodock.app/AudioDock: \[WidgetBridge\]' /data/local/tmp/hl.txt | head -40"
  ```
  （`hilog | grep` 会一直流式挂住，必须先重定向到文件再 grep）
- 真凶：`fs.mkdirSync(dir, true)` 在**目录已存在**时照样抛 `File exists`（EEXIST），不是「存在即返回」。
  结果：第二次及以后的每一次封面落盘都失败 → 卡片拿到空路径 → 占位音符。
  「偶尔能显示」= 首次安装时目录还不存在，那一次 mkdir 成功。
- 修复：`WidgetBridge.ensureDir(dir)`（先 `fs.accessSync` 判断 → mkdir 失败后再 accessSync 校验一次）+ 写前 `fs.unlinkSync` + 写后 `statSync().size` 校验非空。
  `EntryFormAbility.dataImageToFile` 同样修（加 `dirExists` 私有方法）。
- 另一个坑：`COVER_PREFETCH_TIMEOUT_MS` 从 4000 提到 8000——外网 300px 大图 4s 经常超时（`cover prefetch timeout`）。
- ArkTS：`Promise<{bytes, ext}>` 触发 `arkts-no-obj-literals-as-types`，必须显式定义 `interface DownloadedImage`。
- 验证：`ls /data/app/el2/100/base/com.audiodock.app/haps/entry/files/widget_covers` 看到 9 个新 webp（1–2.4KB）；
  日志 `prefetchCover ok file=true dataImage=16647B`，无 File exists / 无 timeout。
- 构建+安装验证：`assembleHap BUILD SUCCESSFUL` + `hdc install -r <hap>`。

## 卡片封面跨进程通道（file:// ❌ → data: URI ✅）

- 之前：列表封面走 `file:// /data/storage/el2/base/...`，卡片进程 `resolve file miss`。
- 根因：卡片渲染在 `com.ohos.formrenderservice` 进程，`/data/storage/el2/base` 按**进程**映射沙箱视图，formrender 里指向自己的目录，根本读不到主 App 写的文件。
- 三种通道实测：
  1. 网络 URL — 卡片进程 Image 加载不可靠（官方文档"部分场景可能存在加载失败"）
  2. `file://` — formrender 沙箱不通用
  3. **`data:` URI 内联 base64** — 随 FormBindingData 跨进程传，唯一稳定 ✅
- 修复：列表封面统一改 `resolveCoverToDataImage(cover, 96)` → `getImageUrl(cover, 96)` → download → `data:image/webp;base64,...`。96px 每张 1-3KB，5 条列表 + 一首正在播放（300px ≈ 15KB base64）远低于 FormBindingData 上限。
- `EntryFormAbility.restoreNowPlayingFromPersistedState` 也只推 `dataImage` / `http`，不再拼 file://。
- `lastCoverFile`（落盘的 file://）保留为兜底，但推送优先级 `dataImage` > `file` > `http`。

## 卡片播放/暂停按钮不变（真凶：togglePlay pause 分支不同步 state）

- 现象：歌曲能暂停/播放，但卡片按钮图标始终不变（一直显示 play ▶）。
- 排查过程：
  1. 在卡片 smallView 加红色调试 Text `DBG p=F t=...`，推送链路验证通（push isPlaying=false 卡片显示 play）。
  2. 临时把 `WidgetBridge.syncNowPlaying` 里 `isPlaying` 硬编码 `true`，卡片**正确**变成 pause ⏸——证明推送链路、LocalStorage、WidgetIcon 切换全部正常。
  3. 真正的根因在 `PlayerStore.togglePlay`：

```typescript
// 旧代码：pause 分支只设 isPlaying，不设 state
if (this.state === 'playing') { await audioBackend.pause(); this.isPlaying = false; }
else { await audioBackend.play(); this.isPlaying = true; }
```

- 如果 `onStateChange('paused')` 回调延迟或丢失，`state` 卡在 `'playing'`，下次 togglePlay 永远走 pause 分支 → isPlaying 永远 false → 按钮永远 play。
- 修复：用 `this.isPlaying` 判断（更准确），并显式同步 `this.state`：

```typescript
if (this.isPlaying) {
  await audioBackend.pause();
  this.isPlaying = false;
  this.state = 'paused';
} else {
  await audioBackend.play();
  this.isPlaying = true;
  this.state = 'playing';
}
```

- 这样无论 `onStateChange` 何时到达，togglePlay 都基于真实 isPlaying 判断，且 state 永远同步。
- 验证：临时硬编码推送 isPlaying=true → 卡片按钮正确变成 pause ⏸ + 调试 Text `p=T`。修复 togglePlay 后从桌面截图能看到正确的播放状态切换。

## 播放/暂停按钮图标真正根因（11:20 修复并真机验证通过）

上一轮修 togglePlay 后用户反馈"还是没切换"。真机诊断（hdc uitest 点击卡片 + hilog + 截图）：
- 日志显示 `widget call: action=play` → `syncNowPlaying isPlaying=true` → `updateForm 320642186` 全链路正常，formrenderservice 也 `Render form` 了；
- 且两次点击分别发出 play/pause（说明卡片内 `this.isPlaying` 变量确实更新了，onClick 读到的是新值）；
- 但截图里图标永远是 ⏸ 不变 → **变量更新、UI 不重绘**。

**根因：卡片渲染管线里带参 @Builder 是按值快照**——`playButton(size, showBg, hitPad)` / `transportRow(iconSize, hitPad)` / `iconBtn(icon, method)` 这类带参 builder 体内的内容不会对 `this.isPlaying` 建立订阅，参数（图标名三元表达式）在首次渲染时固化。无参 @Builder 里的属性绑定（如 `Text(this.title)`）才有响应式（这也是标题/封面一直能更新的原因）。

**修复（4 个卡片统一）**：播放/暂停、模式、点赞图标全部改为「无参 @Builder + 双 Image + `.visibility(三元)` 互斥切换」（卡片 @Builder 体内不允许写 if，visibility 绑定是响应式的）：
- AudioDockPlayerCard：拆出 `transportRowSmall/Medium`、`playButtonSmall/Medium/Large`（无参），`modeButton`/`likeButton` 改 4/2 个 Image visibility 切换，删除 modeIcon helper；prev/next 等静态图标保留带参 iconButton（不需要刷新）。
- LatestCard/PlaylistCard `headerPlayButton`、PlayerHistoryCard 新增 `playPauseBtn`（替代带参 iconBtn 的动态图标调用），同样 visibility 双 Image。

**验证**：装包后 hdc 点击卡片：▶(暂停)→点击→⏸(播放，状态栏媒体胶囊出现)→点击→▶，双向切换正常。

**教训**：排查卡片 UI 不更新时，先用 onClick 发出的 action 判断「变量是否更新」——变量新而 UI 旧 = builder 响应式问题（查带参 @Builder）；变量旧 = 数据推送问题（查 updateForm/KV）。另外注意：**同一文件的多个 Edit 不能并行发**，会互相覆盖（本次因此丢了两处替换导致第一次构建失败）。

## 歌单封面/App 内播放列表修复（11:55 完成并真机验证）

用户报三个问题：①歌单小部件无封面 ②App 我的 tab 播放列表无封面 ③App 内点歌单无法进详情页。

**根因**：
1. **封面**：后端 `GET /playlists`（PlaylistService.findAll）不返回顶层 `cover`/`trackCount`，返回的是 `tracks: [{id, cover}]`（前 4 首）+ `_count: {tracks}`。HarmonyOS 的 PlaylistDto 没声明这两字段，App 和小部件都取 `playlist.cover`（永远 undefined）。
2. **点击无反应**：PersonalTab.onRowClick 用 `if (this.carNavCallback)` 判断是否走车机右栏，但 MainPage **无条件**注入 carNavCallback → 手机端点击走了车机分支（只设置 carDetailName，手机布局不渲染右栏）→ 什么都没发生。HomeTab 的正确写法是门控 `carModeEnabled`。

**修复**：
- `features/network/.../playlist.ets`：PlaylistDto 增加 `tracks?: TrackDto[]` 和 `_count?: PlaylistCount`（注意 PlaylistDetailPage 有 `interface PlaylistDetail extends PlaylistDto { tracks: TrackDto[] }`，tracks 类型必须保持 TrackDto[] 才兼容）。
- PersonalPage：ListRow 新增 `coverAt(i)`（第 i 首曲目封面，不足回退第一首）；subtitle() 歌单分支返回 `${_count.tracks ?? tracks.length} 首`；堆叠封面三层改用 coverAt(2/1/0) 不同封面；PersonalTab 增加 `@StorageLink('carModeEnabled')`，onRowClick 改为 `if (this.carModeEnabled && this.carNavCallback)`（歌单+专辑两个分支都改）。
- WidgetBridge.syncPlaylists：封面取 `it.cover ?? tracks[0].cover`，计数取 `_count?.tracks`。
- 真机验证：小部件歌单行封面+"2 首" ✓；App 我的 tab 堆叠封面+计数 ✓；点击进 PlaylistDetail（封面墙+播放全部+曲目列表）✓。「开心的时候听」0 首属真实空歌单。

**环境注意**：本会话 shell 的 PATH 丢了 hdc，用全路径 `/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/hdc` 或先 export。
