# 2026-11-02

## mobile 播放详情页播放数秒闪退（UI 主题插件 vinyl 封面）

- 现象：Android 真机激活 UI 主题插件（coverStyle=vinyl）后，播放详情页播放数秒闪退。
- 定位：adb logcat -b crash 抓到 `TypeError: undefined is not a function at VinylCoverTsx2`，发生在 worklets `AnimationFrameCallback.onAnimationFrame`（UI 线程动画帧回调里 JS 异常，无 RN 错误边界 → 直接杀进程）。
- 根因：`apps/mobile/src/components/VinylCover.tsx` 的 `spin` worklet 在 withTiming 完成回调里递归调用自身。worklet 闭包无法把「组件内的 worklet 引用」序列化到 UI 线程（拿到 undefined），动画跑完一圈回调触发即崩。
- 修复：改为 `withRepeat(withTiming(current+360, {duration:8000, linear}), -1, false)`，启动前先把 `rotation.value` 归一化到 [0,360)（视觉角度不变，withRepeat 每轮从 startValue 重转一圈）；暂停仍 cancelAnimation 停在当前帧。已验证 reanimated 4.1.6 repeat.ts 源码：reverse=false 时每轮从 animation.startValue 重启内层动画。
- **教训（通用）**：Reanimated worklet 内禁止递归引用自身/同组件其他 worklet；无限循环动画一律用 withRepeat，不要手写回调递归。
- 验证路径：手机装的是 release 包（v1.2.7，不可 debug），改动为纯 JS，gradle assembleRelease 重打包后 adb install -r 覆盖安装验证。

## CI 安卓打包失败：react-native-carplay Kotlin 编译错误

- 报错：`RCTTemplate.kt:309:31 Argument type mismatch: ReadableMap? vs ReadableMap`（CI 完整错误其实有 10+ 处，同类型）。
- 根因：RN 0.81 给 `ReadableArray.getMap(i)/getString(i)` 等加了 @Nullable 注解，`TimingModule.onHostResume` 被移除；carplay 2.4.1-beta.0 的 Android 代码按旧平台类型写的，全部编译不过。
- 修复：`pnpm patch react-native-carplay@2.4.1-beta.0`，产出 `patches/react-native-carplay@2.4.1-beta.0.patch`，并在 pnpm-workspace.yaml 显式注册 patchedDependencies（patch-commit 只写了 lockfile，不保证 CI 生效）。改动：所有 `getMap(i)`/`getString(i)` 直接传参处加 `!!`；CarPlaySession `getJSModule(...)` 改 `?.runApplication`；删除已无的 `timingModule!!.onHostResume()` 及 TimingModule import。
- 验证：删 `apps/mobile/android/build/generated/autolinking`（react-native config 按 realpath 缓存了旧 .pnpm 路径，不删会一直编旧代码）→ `:react-native-carplay:compileReleaseKotlin` BUILD SUCCESSFUL。
- 教训：pnpm patch 后若编译仍报旧错，先查 autolinking.json 的 sourceDir 是否指向 `*_patch_hash=*` 目录。

## Docker 流水线 ENOENT patches/

- 症状：引入 patchedDependencies 后 Docker 构建 `pnpm install --frozen-lockfile` 报 `ENOENT /app/patches/react-native-carplay@2.4.1-beta.0.patch`。
- 原因：Dockerfile 分层 COPY 只复制 package.json 系列，没复制 patches/。
- 修复：Dockerfile 三个阶段都补 `COPY patches/ ./patches/`（builder、mini-builder 在 install 前；runner 从 builder 复制，`pnpm install --prod` 也会读补丁）。.dockerignore 未排除 patches/，无需改。
- **通用教训：仓库引入 pnpm patches 后，所有执行 pnpm install 的 CI/Docker 环境都必须能访问 patches/ 目录**。
