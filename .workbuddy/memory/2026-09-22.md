## desktop 多数据源缓存串歌修复

### 问题
A 数据源缓存的歌，切到 B 数据源后播放同 track_id 的歌会播成 A 的（串歌）。

### 根因
desktop 音频缓存 key 全程只用 `track_id`，数据源（serverAddress/baseURL）从不参与：
- 元数据文件名 `{track_id}.json`（cache.rs check_cache）
- 音频落盘 `download/music/<文件名>`（download_track_internal）
- 下载去重 `active_downloads[track_id]`
不同源同 track_id → 共用一份缓存 → 串播。

### 修复（按数据源物理隔离）
- 前端 `https/index.ts` 新增 `getSourceKey()`：baseURL 归一化（去尾斜杠+小写）后 FNV-1a 哈希；同源 web（/api）固定返回 "sameorigin"。
- Rust `TrackMetadata` 加 `source_key`；缓存元数据文件名 `{sourceKey}_{trackId}.json`；音频落盘加 `src_<key>/` 前缀目录。
- `check_cache` 命中前校验 metadata.sourceKey == 当前源（双保险）。
- `active_downloads` key、`cache_list`（Downloads 页只列当前源）同样按源隔离。
- `cleanup_orphan_cache` 兼容 `src_<key>/` 子目录 .tmp 清理。
- 向后兼容：source_key 空（旧前端/旧缓存）退化裸 track_id。

### 验证
- cargo check 通过；desktop tsc 零错误。
- 落盘路径示例：A 源 `download/src_xxx/music/5.mp3`，B 源 `download/src_yyy/music/5.mp3`，物理隔离。

### 注意
- git push 被 SSH host key 确认拦截（需用户本地 push）。提交在 feat/test：e9d489ec。
- 旧缓存（无 sourceKey 的 `{trackId}.json`）在新源下不会命中（源校验挡住），会重新下载到新隔离目录，旧文件残留属正常，可在设置页清缓存释放。

## mobile / hm 同款修复（提交 595f27b6）

### 确认
mobile（`{trackId}.{ext}` + AsyncStorage 按 t.id）和 hm（`{rootDir}/audio/{trackId}.{ext}` + KV offline_tracks）同样只认 track_id、无源隔离，都会串歌。

### 修复（与 desktop 一致）
- 三端统一 getSourceKey()：baseURL/serverAddress 归一化后 FNV-1a 32bit → base36。mobile 从内存态 activeBaseURL 同步算（https/index.ts）；hm 从 kvStore 读 serverAddress 异步算（utils/device.ets）。
- mobile：文件名 `{sourceKey}_{trackId}.{ext}`；cachedTrackIds/downloadPromises/OFFLINE_TRACKS_KEY 全按源；getDownloadedTracks/removeDownloadedTrack 按源过滤。
- hm：FileCache 全方法加可选 sourceKey（文件名带源前缀）；downloadService/trackResolver/PlayerStore（边播边缓存+预下载）注入 sourceKey；DownloadedMeta 加 sourceKey。
- hm RDB 的 downloaded_track 表是死代码（无人调用 addDownloaded/listDownloaded），不用改 schema。

- mobile tsc 6 个错误全是存量（artist/[id]/member-benefits/webdav-sources/SkeletonBlock/networkUtils），与本次无关。
- hm hvigor assembleHap 编译通过。
