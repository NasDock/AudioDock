### 媒体鉴权（核心难点）
飞牛 `/static/cover`、`/track/stream` **只认 `Authorization` 头**（query token / Cookie music-token 实测全 401）。RN 各链路都支持 headers：
- `RN <Image source={{uri, headers}}>`、`<Image source={getImageSource(...)}>`（新增统一入口，替代 14 个文件里约 45 处裸 `getImageUrl`）
- `expo-image` 的 `source.headers`
- `expo-file-system` `downloadAsync(url, path, {headers})`（封面/音频缓存）
- `react-native-track-player` 的 `Track.headers`（**只有 url 支持，artwork 不支持** → 通知栏封面走「落盘 + updateMetadataForTrack(activeIndex)」，下标用 `getActiveTrackIndex()` 现取，因为起播后旧曲会被移除、下标会前移）
- CarPlay：车机自己拉图（`imgUrl` 只能是 URL/本地路径）→ 列表构建前先把封面落盘再给本地路径。

### 三个平台级坑（踩坑记录）
1. **RN 全局 `URL` 是存根**：`Libraries/Blob/URL` 只有 getter 没有 setter，`url.protocol = "https:"` 在严格模式直接抛 `TypeError`。→ `resolveFnosServer()` 已重写为**纯字符串解析**（不用 `new URL()`），mobile 的 `normalizeFnosAddress()` 直接复用它，端侧不再写第二份。
2. **`Cookie: mode=relay` 必须显式关 credentials**：RN 的 XHR 默认 `withCredentials=true` → Android OkHttp 在 cookie jar 非空时用 jar 的 cookie **覆盖**手动设的 Cookie 头 → 中继又被 302 到登录页。→ `fetch(..., {credentials:"omit"})` / axios `withCredentials:false`（RN 走 `CookieJar.NO_COOKIES`，手动头原样发出）。iOS 侧 `RCTHTTPRequestHandler` 的重定向回调会把 `allHTTPHeaderFields` 整个替换（Authorization 也丢），但带对 cookie 就不发生 302。
3. **中继裸请求要自己补 relay cookie**：`FnosClient.buildHeaders()` 只覆盖适配器自己发的请求；端侧裸请求（连通性探测、`<Image>` 封面）必须手动带 `Cookie: mode=relay`。→ `getMediaHeaders()` 中继地址补 `mode=relay; music-token=<token>`；`checkServerConnectivity` 探测带 `Cookie: mode=relay` 并校验响应体 `code === 0`（中继没放行时 302 → fetch 跟随 → 200 + HTML，只判状态码会误判「连上了」）。

## 飞牛源「没主题色 + 没歌词」修复（同日追加）

用户反馈：飞牛音乐**没有展示封面主题色，没有展示歌词**。两个独立根因，都在 mobile 端。

### 根因 1：本地取色链路没带鉴权头 → 飞牛封面 401
`apps/mobile/src/utils/dominantColorLocal.ts` 是**纯本地**算主题色/磨砂图的（下载封面 → `jpeg-js`/`upng-js` 纯 JS 解码 → 32×32 采样取色），这条链路自己发 HTTP，**不经过 `FnosClient`**，所以 `FnosClient.buildHeaders()` 自动补的 `Authorization` / `Cookie: mode=relay` 全都没有。
现象特征：**封面能显示（走 `getImageSource()` 的组件带头）但播放页没主题色** —— 这就是判据。
修法：`FileSystem.downloadAsync(url, target, { headers: getMediaHeaders() })`（非飞牛源 `getMediaHeaders()` 返回 `{}`，不影响其它数据源）。
附带：加 content-type 校验（非 `image/` 直接判失败）—— 中继缺 `mode=relay` 时网关 302 到登录页，跟随后是 `200 + HTML`，别把登录页当图片解码。

### 根因 2：飞牛列表接口不带 lyrics，mobile 没有懒加载
飞牛 `/track/list` 等**不返回 `lyrics`**，歌词只有单曲接口 `GET /lyric/list?trackGUID=<guid>`（返回 `{list:[{content}]}`，LRC 文本）。desktop 端早就有懒加载（`components/Player/index.tsx`），**mobile 端漏了** → 飞牛歌曲播放页永远「无歌词」。
修法（`apps/mobile/src/context/PlayerContext.tsx`）：
- 切歌时按需 `getTrackLyrics(track.id)`（来自 `@soundx/services`）；
- 拿到后**并回当前曲目** `setCurrentTrackState({...track, lyrics})` → 播放页歌词面板、车机歌词（CarWith/Android Auto/CarPlay）、歌词字号预览三处共用同一份，不用分别改；
- 带 `Map<trackId, lyrics>` 内存缓存，切回同一首不重复请求；
- 其它数据源 `Track.lyrics` 已内建，命中即跳过（`isFnosSource(getCurrentSourceType())` 守门）。
