## 修复 hm 桌面小部件"黄色背景白字"问题（真根因：ArkUI hex 颜色格式错误）

**用户反馈**：改了 `colorMode` 重新构建后还是黄色背景白字。

**真根因**：ArkUI 的 8 位 hex 颜色格式是 **`#AARRGGBB`（透明度在前）**，而代码里全部按 CSS 习惯写成了 **`#RRGGBBAA`（透明度在后）**。

验证：`#FFFFFF14`（本意白色 8% 高光）按 AARRGGBB 解析 = alpha `FF`（不透明）+ RGB `FFFF14` = **纯黄色**——正好解释"黄色背景白字"。`WidgetBackground.ets` 顶层叠了这层"高光"，把整个卡片刷成了黄色。

**修复**：把所有 8 位 hex 从 RRGGBBAA 改成 AARRGGBB：
- `#FFFFFF14` → `#14FFFFFF`（白 8%）
- `#FFFFFF1A` → `#1AFFFFFF`（白 10%）
- `#FFFFFF26` → `#26FFFFFF`（白 15%）
- `#FFFFFF80` → `#80FFFFFF`（白 50%）
- `#FFFFFFB3` → `#B3FFFFFF`（白 70%）
- `#00000038` → `#38000000`（黑 22%）

**改动文件**（8 个）：
- `widgets/WidgetBackground.ets`（2 处）
- `widgets/WidgetConstants.ets`（7 个常量）
- `widgets/WidgetCover.ets`（2 处）
- `widgets/PlayerHistoryCard.ets`（2 处）
- `widgets/PlaylistCard.ets`（2 处）
- `widgets/LatestCard.ets`（3 处）
- `widgets/LockedCard.ets`（1 处）
- `widgets/AudioDockPlayerCard.ets`（1 处）

**教训**：ArkUI/HarmonyOS 的颜色 hex 是 AARRGGBB（Android/iOS 原生惯例），不是 CSS 的 RRGGBBAA。跨端对齐样式时必须检查目标平台的颜色格式约定。之前改的 `colorMode: dark` 保留无害（强制深色模式，避免系统反色干扰）。

**生效步骤**：重新构建 + 安装 HAP + 删掉桌面旧卡片重新添加。

## 修复小部件 emoji 按钮 + 「未在播放」状态问题

**问题 1：所有按钮是 emoji**
代码里所有播控按钮（⏮/⏸/▶/⏭/♥/♡/⇄/⟲/↺/♕/♪/↻）都是 Unicode 字符，HarmonyOS 渲染成系统 emoji，和 iOS SF Symbols 矢量图标差太远。

**修复**：新增 `widgets/WidgetIcon.ets`，用 Path 绘制矢量图标（对齐 SF Symbols 视觉），覆盖 play/pause/prev/next/heart/heart.fill/shuffle/repeat/repeat.1/list/music/crown/refresh 共 12 种。所有 5 个卡片文件（AudioDockPlayerCard/PlaylistCard/PlayerHistoryCard/LatestCard/LockedCard）+ WidgetCover 的占位音符全部替换。

**问题 2：状态一直显示「未在播放」**
`widgetBridge.install()` 只在 `EntryAbility.onCreate` 调一次，之后只有 `playerStore` 变化才触发 `syncNowPlaying`。如果用户没启动过主 App（或启动了还没播放），kvStore 里 `widget_now_playing` 就是空的（`updatedAt = 0`），卡片永远显示「未在播放」。

**修复**：`EntryFormAbility.loadSnapshotForKind` 的 PLAYER 分支里，如果读到空数据（`updatedAt === 0`），主动调用新增的 `restoreNowPlayingFromPersistedState()` 从 `playbackState_MUSIC`（playerStore.persistState() 写入的持久化状态）恢复上次的播放快照。这样卡片至少能显示上次的歌曲信息 + 播放按钮（而不是「未在播放」占位）。

**注意**：
- `restoreNowPlayingFromPersistedState` 恢复的是「上次的播放状态」，不是「当前正在播放」，`isPlaying` 恒为 false（因为主 App 没在跑）
- 卡片进程和主 App 是独立进程，`EntryFormAbility` 不能直接 import `playerStore`（拿不到主 App 的内存状态），只能通过 kvStore 间接恢复
- HarmonyOS 没有 iOS SF Symbols 那种按名字引用系统图标的能力，媒体控制图标系统也没内置，必须用 Path 绘制矢量图形

## 修复 ArkTS 编译错误（对象字面量不能当类型）

`EntryFormAbility.restoreNowPlayingFromPersistedState` 里用内联对象字面量当类型（`{ queue?: Array<{...}> }`），ArkTS 严格模式报 `arkts-no-obj-literals-as-types`。

**修复**：把内联类型抽成显式 interface（`PersistedTrackLite` / `PersistedPlaybackState`），JSON.parse 的 `as` 断言指向 interface。

**构建验证**：`hvigorw assembleHap` 通过 ✅；真机验证卡片显示「疯了的大伯」+ 暂停图标，与主 App 播放队列第 3 首一致。

**真根因（关键发现）**：
1. **`ohos.extra.param.key.form_id` 这个 key 不存在**！官方常量是 `formInfo.FormParam.IDENTITY_KEY = "ohos.extra.param.key.form_identity"`。代码误用导致 formId 恒为 `""` → `updateForm('')` 报 "The formId is invalid" → 卡片永远停在首屏骨架。**必须用 `formInfo.FormParam.IDENTITY_KEY` / `NAME_KEY` / `DIMENSION_KEY` 三个常量**。
2. **`DIMENSION_KEY` 传的是 FormDimension 数字枚举**（`Dimension_2_2 = 2` / `Dimension_4_4 = 4`），不是 `"2*2"` 这种。要归一化：`1→1*2, 2→2*2, 3→2*4, 4→4*4, 5→2*1`，否则卡片布局判断恒走 2x2。
3. **preferences 是每进程一份内存缓存实例**。跨进程写入后另一进程仍读旧缓存。修复：调用前 `preferences.removePreferencesFromCache(ctx, STORE_NAME) + getPreferences()` 重载。已在 `PreferencesStore` 封装为 `pull()` / `getFresh()` / `getJSONFresh()`，主 App 读 formId 注册表、卡片进程读 `widget_now_playing` 都必须走 fresh 系列。
4. **持久化脏数据**：旧代码把 `[""]` 写进了 `widget_form_ids_${kind}`，preferences 持久化下来重装 App 不会清。修复：`getFormIdsForKind` 过滤空 formId 并重写。

## 修复 App 播放状态不同步到卡片（订阅机制跨不了进程）

**用户反馈**：改了 formDimension 和反向索引后，卡片还是不同步。

**真根因**：`WidgetBridge.install()` 只在 `EntryAbility.onCreate` 调一次，之后只有 `playerStore` 的**内存状态变化**才触发 `syncNowPlaying`。但：
1. 如果主 App 没启动过，`playerStore` 根本没初始化，`subscribe` 永远不会触发
2. 即使主 App 启动了，`playerStore` 是**内存对象**，它的 `subscribe` 回调只在主 App 进程内有效，**卡片进程收不到**
3. `syncNowPlaying` 里 `playerStore.view()` 读的是**主 App 进程的内存**，如果主 App 没启动，`view()` 返回空队列

**参考文章方案**（ost.51cto.com/posts/40773）：App 端**任何**播放状态变化都走「写 Preferences → 批量 `formProvider.updateForm`」的 `commit()` 三连，**不依赖** `playerStore.subscribe` 这种内存订阅（因为卡片进程和 App 进程内存不共享，订阅根本跨不了进程）。

**修复**：
1. `PlayerStore.notify()` 里加 `pushToWidget()` 钩子，任何状态变化（play/pause/next/prev/mode/like）都主动推卡片
2. `pushToWidget()` 用动态 `import('../services/WidgetBridge')` 避免循环依赖，调 `widgetBridge.syncNowPlayingFromStore()` 立即推
3. `notify()` 里加守卫：只在 `isPlaying || queue.length > 0` 时才推，避免 `loadPersistedState` 恢复状态时推空状态覆盖卡片数据
4. `WidgetBridge` 新增 `syncNowPlayingFromStore()` 方法，和 `syncNowPlaying()` 的区别是「立即触发」vs「schedule 合并触发」

**构建验证**：`hvigorw assembleHap` 通过 ✅；真机验证卡片显示「疯了的大伯」+ 暂停图标，与主 App 播放队列第 3 首一致。

**真根因**：`WidgetBridge.install()` 只在 `EntryAbility.onCreate` 调一次，之后只有 `playerStore` 的**内存状态变化**才触发 `syncNowPlaying`。但：
1. 如果主 App 没启动过，`playerStore` 根本没初始化，`subscribe` 永远不会触发
2. 即使主 App 启动了，`playerStore` 是**内存对象**，它的 `subscribe` 回调只在主 App 进程内有效，**卡片进程收不到**
3. `syncNowPlaying` 里 `playerStore.view()` 读的是**主 App 进程的内存**，如果主 App 没启动，`view()` 返回空队列

**参考文章方案**（ost.51cto.com/posts/40773）：App 端**任何**播放状态变化都走「写 Preferences → 批量 `formProvider.updateForm`」的 `commit()` 三连，**不依赖** `playerStore.subscribe` 这种内存订阅（因为卡片进程和 App 进程内存不共享，订阅根本跨不了进程）。

**修复**：
1. `PlayerStore.notify()` 里加 `pushToWidget()` 钩子，任何状态变化（play/pause/next/prev/mode/like）都主动推卡片
2. `pushToWidget()` 用动态 `import('../services/WidgetBridge')` 避免循环依赖，调 `widgetBridge.syncNowPlayingFromStore()` 立即推
3. `notify()` 里加守卫：只在 `isPlaying || queue.length > 0` 时才推，避免 `loadPersistedState` 恢复状态时推空状态覆盖卡片数据
4. `WidgetBridge` 新增 `syncNowPlayingFromStore()` 方法，和 `syncNowPlaying()` 的区别是「立即触发」vs「schedule 合并触发」

**构建验证**：`hvigorw assembleHap` 通过 ✅；真机验证卡片显示「疯了的大伯」+ 暂停图标，与主 App 播放队列第 3 首一致。

**真根因（关键发现）**：
1. **`ohos.extra.param.key.form_id` 这个 key 不存在**！官方常量是 `formInfo.FormParam.IDENTITY_KEY = "ohos.extra.param.key.form_identity"`。代码误用导致 formId 恒为 `""` → `updateForm('')` 报 "The formId is invalid" → 卡片永远停在首屏骨架。**必须用 `formInfo.FormParam.IDENTITY_KEY` / `NAME_KEY` / `DIMENSION_KEY` 三个常量**。
2. **`DIMENSION_KEY` 传的是 FormDimension 数字枚举**（`Dimension_2_2 = 2` / `Dimension_4_4 = 4`），不是 `"2*2"` 这种。要归一化：`1→1*2, 2→2*2, 3→2*4, 4→4*4, 5→2*1`，否则卡片布局判断恒走 2x2。
3. **preferences 是每进程一份内存缓存实例**。跨进程写入后另一进程仍读旧缓存。修复：调用前 `preferences.removePreferencesFromCache(ctx, STORE_NAME) + getPreferences()` 重载。已在 `PreferencesStore` 封装为 `pull()` / `getFresh()` / `getJSONFresh()`，主 App 读 formId 注册表、卡片进程读 `widget_now_playing` 都必须走 fresh 系列。
4. **持久化脏数据**：旧代码把 `[""]` 写进了 `widget_form_ids_${kind}`，preferences 持久化下来重装 App 不会清。修复：`getFormIdsForKind` 过滤空 formId 并重写。

**端到端日志验证关键路径**：
```
[EntryFormAbility] onAddForm kind=widget_player id=1874482483 dimension=2*2   ← formId 不再是空
[WidgetBridge] registerForm name=widget_player id=1874482483 dim=2*2 all=1     ← 注册成功
[WidgetBridge] updateForm 1874482483 kind=widget_player dim=2*2               ← 推送成功
[WidgetBridge] syncNowPlaying isPlaying=false idx=2 queue=75                  ← 播放状态读到
```

**改动文件**：
- `apps/harmony/features/storage/src/main/ets/PreferencesStore.ets`（+pull/getFresh/getJSONFresh）
- `apps/harmony/products/entry/src/main/ets/formability/EntryFormAbility.ets`（onAddForm 用 formInfo 常量 + 多 key 兜底 + normalizeDimension；loadSnapshotForKind 开头 pull）
- `apps/harmony/products/entry/src/main/ets/services/WidgetBridge.ets`（dynamic import PlayerStore 打破循环依赖 + 全局 formId 索引 + 清洗脏 formId）

## 修复小组件同步最终链路（重复函数定义 + 节流过短）

**问题**：修了跨进程缓存和订阅机制后，卡片还是不同步。

**根因 1：`PlayerStore.schedulePushToWidget` 被定义了两次**（重复函数定义），导致编译失败/运行时异常。

**修复**：删除重复的 `schedulePushToWidget` 定义，只保留一个。

**根因 2：`scheduleSyncNowPlaying` 节流时间 300ms 太短**。进度 tick 每 ~50ms 触发一次 `notify()`，300ms 节流还是会让 `formProvider.updateForm` 每 300ms 调一次，系统 hilog 报 `isReportOverSize,checkFail` 限频拒绝。

**修复**：把节流时间从 300ms 提到 **1000ms**（1 秒一次足够，卡片不需要毫秒级精度）。

**端到端日志验证**：
```
09-04 11:25:18.242 [WidgetBridge] syncNowPlaying isPlaying=true idx=14 queue=75   ← 播放状态读到了
09-04 11:25:18.251 [WidgetBridge] updateForms kind=widget_player ids=1            ← 找到卡片
09-04 11:25:18.258 [WidgetBridge] updateForm 788540225 kind=widget_player dim=2*2 ← 推送成功
（播放中每 ~1 秒推一次，节流生效）
```

**改动文件**：
- `apps/harmony/products/entry/src/main/ets/context/PlayerStore.ets`（删除重复 schedulePushToWidget）
- `apps/harmony/products/entry/src/main/ets/services/WidgetBridge.ets`（scheduleSyncNowPlaying 300ms → 1000ms）

**构建验证**：`hvigorw assembleHap` 通过 ✅；真机验证播放状态实时同步到卡片。

## 下午：参考官方 CardInfoRefresh 示例，修复卡片封面 + 播控

参考 https://gitcode.com/HarmonyOS_Samples/CardInfoRefresh 官方示例，重构卡片数据流：

### 1. 封面渲染三级兜底（WidgetCover.ets / WidgetBackground.ets）
- 新增 `WidgetCoverResolver`：data:base64 → file:// → 绝对 URL（相对路径用模块级 baseUrl 补全）
- 修复 `WidgetBackground` 直接用裸相对路径 `Image(this.cover)` 的 bug（卡片进程无网络栈，必失败）
- `WidgetCover` 不再 import `features_network` 的 `getImageUrl`（卡片进程会拉起整张网络栈），改走 resolver

### 2. 封面预取（WidgetBridge.prefetchCover）
- 主 App 播放到新曲目时：http.createHttp 拉 ARRAY_BUFFER → 写 filesDir/widget_covers/<hash>.webp → 生成 data:image/webp;base64 内联
- FormBindingData 直接带 dataImage，卡片零 IO 渲染（对齐官方「进程侧预取，卡片直读本地」）
- 300px webp 基本 <20KB，远低于 FormBindingData 80KB 上限
- 4s 超时保护：网络差时退化为发网络 URL，不卡 updateForm 主流程

### 3. 播控改 call 事件（对齐官方 this.callee.on 模式）
- EntryAbility.onCreate 注册 `this.callee.on('widgetCommand', handler)`，回包用 `WidgetParcelable implements rpc.Parcelable`
- 4 张卡片的 play/pause/next/prev/mode/like/play_playlist/play_history/play_latest/refresh_latest 全部从 `action:'message'` 改为 `action:'call' + abilityName:'EntryAbility'`
- 指令直达主 App 的 playerStore 单例（message 事件落到 EntryFormAbility 进程，是另一个 playerStore 实例，无法控制主 App 播放）
- 冷启动时序：EntryAbility.onCreate 里先 `restorePromise = playerStore.restoreState()`，call 回调 await 它再执行指令（否则 queue 空，play 落空）

### 4. EntryAbility.initialize 注入 abilityContext
- `AppStorage.setOrCreate('abilityContext', ctx)` 供 WidgetBridge.writeCoverToDisk 取 filesDir
- getContext() 只在 @Component 内可靠，service 类必须从 AppStorage 取

### 关键坑（下次别踩）
- ArkTS 严格模式：postCardAction 的 params 不能写对象字面量 `{a:1}`，必须先 `const params: Record<string,string> = {}` 再逐项赋值（arkts-no-untyped-obj-literals）
- Promise.race 两个分支必须同类型（一个 Promise<Uint8Array> 一个 Promise<void> 会报 void | Uint8Array 不可赋值）
- Uint8Array.buffer 可能带 byteOffset，写文件前必须 slice 出干净 buffer
- fs.mkdirSync(dir, true) 第二参数 true = 递归创建

**构建验证**：`hvigorw assembleHap` 通过 ✅（BUILD SUCCESSFUL in 5s）

## 下午 3：修复列表封面不显示 + 按钮太小

### 列表封面不显示
**根因**：`WidgetCoverResolver.baseUrl` 是模块级变量，主 App 进程赋值后卡片进程看不到（卡片是独立 process），导致相对路径 `/covers/xxx` 解析不出来，列表封面全显示占位音符。

**修复**：
1. `EntryFormAbility.ensureKvAndHttpReady()` 里从 kvStore 读 `serverAddress` 后同步赋值给 `WidgetCoverResolver.baseUrl`（卡片进程自己初始化，不依赖主 App 进程）
2. `WidgetBridge` 新增 `resolveListCover()`：把列表卡片的封面字段从相对路径补全成绝对 URL 再下发（列表封面数量多、体积大，不走 dataImage 预取，直接给绝对 URL 让卡片自己加载网络图）
3. `syncPlaylists/syncHistory/syncLatest` 的 cover 字段统一走 `resolveListCover()`
