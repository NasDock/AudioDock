## Navidrome（Subsonic）音乐源搜索对接

- 根因：`SubsonicMusicAdapter` 没有 `search`/`searchRecord`，`services/search.ts` 回退到 `/track/search`、`/album/search`、`/artist/search`；切第三方源后 baseURL 指向 Navidrome，这些路径不存在 → 搜索一直为空。
- 实现：新增 `packages/services/src/adapter/subsonic/search.ts`，用 Subsonic `search3`（老服务端回退 `search2`）一次取 song/album/artist，`query` + `songCount/albumCount/artistCount`；同关键词并发用 in-flight promise 合并，只发一次请求。歌单无搜索接口，拉 `getPlaylists` 后按 name 本地过滤。
- 搜索历史：新增 `subsonic/search-record.ts`，复用飞牛的端侧存储适配器；给 `FnosSearchRecordAdapter` 加 bucketPrefix 参数（默认 `soundx` 保持飞牛兼容），Subsonic 用 `subsonic`，避免同 baseUrl 串历史。desktop 清历史时同步清本地热词。
- 类型/挂载：subsonic/types.ts 补 `SubsonicSearchResult`、`SubsonicPlaylistList`；`SubsonicMusicAdapter` 挂载 search/searchRecord；更新 interface/search/search-record 注释。
- 验证：`pnpm --dir packages/services build` 通过；本地模拟 Subsonic 服务端跑 `searchAll('周杰伦')` → 3 类结果 + 歌单命中，请求日志确认只发 1 次 search3 + 1 次 getPlaylists；历史增/热词/清空均正常。
- 范围：desktop/mobile/mini 共用该服务层自动生效；Harmony 端搜索仍是自己的 ArkTS httpClient（无 Subsonic 适配器），本轮未改。

### Audiobookshelf 搜索无回显修复（同日追加）
- 根因：v2.38.0 实际响应是 `{ book: [{ libraryItem: {...} }] }`，原 `normalizeSearch()` 只认 `audiobooks/podcasts/books/results`，既漏了单数 `book` 键也没拆 `libraryItem` 外壳 → 解析成空数组。
- 修复：`types.ts` 新增 `AbsSearchEntry` 兼容 wrapper；`search.ts` 的 `normalizeSearch()` 统一拆 `libraryItem/audiobook/podcast/book` 并按 id 去重，`searchAll` 的 3 个并发调用 in-flight 合并为 1 次请求；搜索结果缺 audioFiles 时用 `itemDetail()` 补详情。
- 顺带修流地址：真实 `audioFiles[].index` 从 1 开始，直接当 `?file=` 会跳过第一集；现在按首个 index 自适应 0/1-based，且优先用 `media.tracks[].contentUrl`。
- 验证：mock 改成用户给的真实 `{book:[{libraryItem}]}` + 1-based index，重建 dist 后 `searchAll('三体')` 有曲目/专辑回显，请求日志确认搜索只发 1 次；流 URL 从 `file=0` 开始。
- 艺术家栏追加修复：原 `searchArtists()` 要求作者名包含搜索词（搜书名《三体》时作者「刘慈欣/三体宇宙」不匹配 → 整栏空）。ABS 没有独立 artist 索引，改成从命中的书直接取作者，作者不足再补 `metadata.narrators[]`（id 前缀 `narrator:`），不再二次按名字过滤。mock 验证 `searchAll('三体')` 返回 `artists:[刘慈欣, 主播甲]`。

### Audiobookshelf 单曲列表为空修复（同日追加）
- 根因推断：`/api/libraries/{id}/items` expanded 响应会把每本书全部 audioFiles 带回来（单本 300+ 集约 450KB，120 本 = 几十 MB），隧道/弱网下必超时 → `allItems()` 抛错 → 依赖它的单曲等列表全空（搜索只拉命中书，所以搜索正常）。
- 修复（store + track 分层）：`AbsItemStore.allItems()` 改用 `minified=1`（ABS minified 含 metadata/coverPath/numTracks，不含 audioFiles，已核对 v2.38 Book.toOldJSONMinified）；新增 `itemDetail(id)`（/api/items/{id} + 5min 缓存）、`allItemDetails()`（8 并发分批，单本失败跳过）、`itemById` 详情优先；track 适配器改窗口分页 `tracksWindow(offset,size)`（用 numTracks 记账，窗口内才拉详情）；`getLatestTracks` 按最新书逐本凑满一页；collection 系列兜底也加 minified=1。
- 验证：mock 区分 minified/expanded，列表/单曲/搜索/系列全通过，列表请求只发 minified，详情按需缓存只拉 1 次。
