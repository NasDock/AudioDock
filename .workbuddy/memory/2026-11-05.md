## mobile 播放页磨砂背景对齐 hm：小图源放大法
- 用户实测：mobile 只有渐变色、没有高斯模糊（hm 端 backdropBlur 方案正常）。
- 根因（双重）：① expo-image Android `blurRadius` 被 Glide `BlurTransformation(min(it, 25), 4)` **钳制到最大 25**（ExpoImageViewWrapper.createPropOptions），且模糊作用在解码后的源图上——300px 源图上 25px 模糊、cover 放大到全屏（~3.6x）后视觉等效 ~7px，几乎无感；② 渐变罩层近不透明（0.88~0.97）把模糊层盖死。
- 修复（app/player.tsx）：模糊层改请求 **48px 极小图**（getImageUrl(cover, undefined, 48)，服务端 /image/optimize width 合法区间 [16,1500]）——25px 模糊半径占 48px 图幅 >50%，拉伸全屏后即成强磨砂；渐变罩层改**三段半透明**对齐 hm：暗色 coverColor@0.6→shade(0.55)@0.78→shade(0.22)@0.92，亮色 tint(0.72)@0.55→tint(0.5)@0.72→tint(0.28)@0.88，fallback 黑 0.45/0.65/0.85、白 0.55/0.7/0.9。
- 备忘：mobile 没装 expo-blur；若未来要真·实时模糊可装 expo-blur（Android API 31+ 走 RenderEffect，低版本退化半透明），当前小图放大法零新依赖。

## api 封面取色算法对齐 desktop canvas（a5e9ab90）
- 用户反馈 api 取色偏淡，要求完全对齐 desktop useCoverDominantColor。
- 三处实现对齐：toColorspace('srgb')（广色域/CMYK 封面直接读数值是偏淡偏色主因）+ flatten 黑底（PNG alpha 残留稀释）+ resize(32,32,{fit:'fill',kernel:'cubic'})（对齐 drawImage 强制拉伸与平滑缩放；旧 resize 保宽高比导致非正方形封面采样不一致）。
- 缓存 key bump v2（旧结果作废重算）。实测：库里大量 720×480/456×608 非正方形封面 + 陈奕迅/OneRepublic 等 RGBA PNG 正是偏差来源；规范 sRGB 图新旧结果 ±2。
- 若用户仍嫌"淡"属算法取向（平均色天然偏灰），备选：HSL sat×1.2 饱和度增强（未做）。

## desktop 搜索弹窗暗色白底修复（07b32986）
- 根因：SearchResults 用 `themeSetting === "dark"` 判断背景，但 themeSetting 是用户选项（light/dark/**system**），system+暗色系统时永≠dark → 恒走白底 rgba(255,255,255,0.9)。
- 修复：改用 ThemeContext 的 `mode`（实际生效主题，已解析 system）。两处（历史/热搜面板 + 结果面板）。
- 备忘：desktop 有两个 useTheme——hooks/useTheme 返回字符串（系统主题），context/ThemeContext 返回 {mode, themeSetting, setTheme, toggleTheme}；组件应一律用后者且判断 mode。

- 上述 SearchResults 修复在 CI 编译报错：组件内已有 `const { mode } = usePlayMode()`（TrackType），与 useTheme 解构的 mode 重声明（TS2451）→ 别名 `themeMode`。

## desktop 播放列表详情页表格错位（Win）+ 进度条拖不动
- 现象：Win（125% 缩放，CSS 视口 ~796px）歌单详情页 antd Table 的表头/单元格竖排堆叠，每列各占一行；底栏进度条点击/拖动都不生效。
- 表格：PlaylistDetail 是 desktop 里**最后一个还在用 antd `<Table>` 的歌单列表页**（其余 Favorites/Listened/Downloads/ArtistDetail/Detail 早已迁 TrackList）。已迁移到 TrackList（CSS Grid，列宽由 gridTemplateColumns 内联显式给出，不再依赖 colgroup），顺带获得虚拟列表 + LazyImage 封面。
  - TrackList 新增 `extraMenuItems?: (track) => MenuProps["items"]`，追加到每行「更多」菜单末尾（前插 divider），用于歌单页的「移入其他歌单 / 从歌单移除」。
  - 复现结论：同一份 antd Table 在 Chrome 796px 下渲染正常（display: table-row/table-cell），也试过「删掉 antd cssinjs 全部样式」仍是横排 → 错位是 WebView2 环境特有的，无法本地复现，所以选「换实现」而不是「打 CSS 补丁」。
- 进度条：5d7cc169 起是无依赖自绘细条，用裸 pointerdown + setPointerCapture 手写拖动；WebView2 上 pointerdown 后收不到 move/up，且 `seekFromClientX` 一旦取到 0 宽元素 rect 会算出 NaN（`audio.currentTime = NaN` 直接抛错）→ 既拖不动也点不动。
  - 改法：视觉层保持自绘（rail/buffered/played + 时间气泡），交互层**覆盖一个铺满热区的透明 antd Slider**（min/max=duration、step=1、onChange→handleSeek、handle display:none、rail/track 透明）——点击定位/拖动/方向键全交给 Slider，跨端可靠。
  - handleSeek 加防御：非有限值/负数丢弃，target 用 duration clamp，赋值 try/catch。
  - 热区 12px→14px；`.topProgressSlider` 用 absolute inset 0 覆盖，LESS 里 `:global` 关掉 `.ant-slider-rail/-track` 背景与 handle。
  - 已用 headless Chrome + 合成 pointerdown 验证：50% 处点击 → seek 123s（duration 245）✅。

### 补充：错位的真正来源（用户质疑后复核）
- 用户指出「其它详情页正常、唯独歌单详情页 Win 错位」，质疑我的判断。查 `git show --stat ad6cd07b`（2026-01-13 "chore: 简化播放列表代码"）：那次抽出公共 `TrackList` 时迁了 `components/Detail`(专辑详情)/ArtistDetail/Favorites/Listened/Downloads 五个页面，**文件清单里没有 PlaylistDetail** —— 它是重构遗漏项，一直在用内联的 antd `<Table>`。所以「唯独它坏」不是环境玄学，而是**只有它没走公共组件**。
- 用户提供的 `--ant-display: block` 线索：对照实验（给 th 加 `display: var(--ant-display)`，值=block）渲染结果与用户截图完全一致（每格独占一行、宽度=文字宽）→ 现象的直接原因是单元格 display 被算成 block。但该变量在 antd 里只有 Grid/Col 写+读（`antd/es/grid/style/index.js:106`），Table 内部不消费，src 里也没人用 `var(--ant-display)`；它出现在 table 的 computed 上只是因为 table 在 `<Col span={24}>` 内、CSS 变量会继承。属"证人"不属"凶手"；mac Chrome 796px 复现不出（也试过整体删掉 antd cssinjs 仍横排）。
- 防御：`styles/global.less` 新增 antd Table 的 display 兜底（`.ant-table table/theader/tbody/tr/th/td` 全部 `!important` 钉回表格语义，只声明 display）。若 Win 上会员权益/会员详情/任务中心/TTS/用户管理/小米音箱设置这些 antd Table 页面出现同样竖排，可直接压掉；将来若用 antd virtual 表格需排除（tbody tr 依赖 flex）。当前项目无 virtual/fixed 列。
