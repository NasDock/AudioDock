## mobile 播放页磨砂背景对齐 hm：小图源放大法
- 用户实测：mobile 只有渐变色、没有高斯模糊（hm 端 backdropBlur 方案正常）。
- 根因（双重）：① expo-image Android `blurRadius` 被 Glide `BlurTransformation(min(it, 25), 4)` **钳制到最大 25**（ExpoImageViewWrapper.createPropOptions），且模糊作用在解码后的源图上——300px 源图上 25px 模糊、cover 放大到全屏（~3.6x）后视觉等效 ~7px，几乎无感；② 渐变罩层近不透明（0.88~0.97）把模糊层盖死。
- 修复（app/player.tsx）：模糊层改请求 **48px 极小图**（getImageUrl(cover, undefined, 48)，服务端 /image/optimize width 合法区间 [16,1500]）——25px 模糊半径占 48px 图幅 >50%，拉伸全屏后即成强磨砂；渐变罩层改**三段半透明**对齐 hm：暗色 coverColor@0.6→shade(0.55)@0.78→shade(0.22)@0.92，亮色 tint(0.72)@0.55→tint(0.5)@0.72→tint(0.28)@0.88，fallback 黑 0.45/0.65/0.85、白 0.55/0.7/0.9。
- 备忘：mobile 没装 expo-blur；若未来要真·实时模糊可装 expo-blur（Android API 31+ 走 RenderEffect，低版本退化半透明），当前小图放大法零新依赖。

## api 封面取色算法对齐 desktop canvas（a5e9ab90）
- 用户反馈 api 取色偏淡，要求完全对齐 desktop useCoverDominantColor。
- 三处实现对齐：toColorspace('srgb')（广色域/CMYK 封面直接读数值是偏淡偏色主因）+ flatten 黑底（PNG alpha 残留稀释）+ resize(32,32,{fit:'fill',kernel:'cubic'})（对齐 drawImage 强制拉伸与平滑缩放；旧 resize 保宽高比导致非正方形封面采样不一致）。
- 缓存 key bump v2（旧结果作废重算）。实测：库里大量 720×480/456×608 非正方形封面 + 陈奕迅/OneRepublic 等 RGBA PNG 正是偏差来源；规范 sRGB 图新旧结果 ±2。
- 若用户仍嫌"淡"属算法取向（平均色天然偏灰），备选：HSL sat×1.2 饱和度增强（未做）。

## desktop 搜索弹窗暗色白底修复（07b32986）
- 根因：SearchResults 用 `themeSetting === "dark"` 判断背景，但 themeSetting 是用户选项（light/dark/**system**），system+暗色系统时永≠dark → 恒走白底 rgba(255,255,255,0.9)。
- 修复：改用 ThemeContext 的 `mode`（实际生效主题，已解析 system）。两处（历史/热搜面板 + 结果面板）。
- 备忘：desktop 有两个 useTheme——hooks/useTheme 返回字符串（系统主题），context/ThemeContext 返回 {mode, themeSetting, setTheme, toggleTheme}；组件应一律用后者且判断 mode。

### CI 修复（6e786191）：desktop 类型检查必须用 tsc -b
- 上述 SearchResults 修复在 CI 编译报错：组件内已有 `const { mode } = usePlayMode()`（TrackType），与 useTheme 解构的 mode 重声明（TS2451）→ 别名 `themeMode`。
- 教训：desktop tsconfig 是 solution 风格（references），`tsc --noEmit` 实际不检查任何文件（我之前验证漏报的原因），**验证必须 `npx tsc -b`（与 CI 一致）**。
