# 2026-09-09

## STRM 播放问题排查

用户反馈：api 子项目配置了 STRM_ADDRESS=http://192.168.1.12:5244（内网 Alist 地址）。内网网页端播放 strm 没问题，内网手机网页播放也没问题，但**内网外网下鸿蒙 app 播放不了，外网下的手机网页端也播放不了**。

排查结论：
- `packages/utils/src/index.ts` 扫描 .strm 时，把 `STRM_ADDRESS + 相对路径` 拼成完整 URL 写入 DB 的 `track.path`。
- 后端 `/track/stream/:id` 对 `path.startsWith('http')` 的曲目直接 `proxyStream(track.path)`，即服务端代理到 Alist 内网地址。
- 网页端（desktop/mini）播放时走 `/track/stream/:id` 代理 → 内网 OK；外网也能代理，但代理出口是服务器所在网络，如果服务器在外网访问不到 192.168.1.12，则外网代理也失败。
- 鸿蒙端 `resolveTrackUrl` 对 http(s) path **直接返回原 URL 给 AVPlayer**，不走 `/track/stream` 代理 → 客户端直接访问 192.168.1.12 → 外网/鸿蒙都失败。
- mobile 端 `buildTrackPlaybackUrl` 同样直接返回 track.path → 外网手机网页也失败。

根因：STRM_ADDRESS 是内网地址，导致 DB 里存的 track.path 是内网 URL，客户端直连失败。

修复方向：
1. 让 STRM 曲目统一走 `/track/stream/:id` 代理（客户端不直接暴露内网地址）。
2. 或把 STRM_ADDRESS 配成外网可访问地址（如公网域名/反向代理）。
3. 鸿蒙端 `resolveTrackUrl` 对 strm 曲目不要直接返回 path，而是走 `/track/stream/:id`。
