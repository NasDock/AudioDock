# 2026-09-17

## desktop ArtistDetail 报 Invalid hook call 修复
- 根因：`apps/desktop/src/pages/ArtistDetail/index.tsx` 在模块顶层（组件函数体外）调用了 `theme.useToken()` hook，模块加载时即执行 → React Invalid hook call。
- 修复：把 `const { token } = theme.useToken()` 挪进 `ArtistDetail` 组件函数体首行。`token` 仅用于分页 sentinel 的 `colorTextSecondary`。
- 排查：全项目 grep 确认其他 useToken 均在组件内，无同类问题。

- 报错 `Failed to find package 'tools'` → sdkmanager exit 1。
- 根因：GitHub 把 `ubuntu-latest` 迁到 ubuntu-24.04，Google 已下线 sdkmanager 的 `tools` 包，v3 版 action 还在尝试安装它。

## desktop 生产环境无法流转修复
- 现象：本地开发 desktop → hm/mobile 正常；生产环境 desktop 无法流转（hm/mobile 互转正常）。
- 根因：`apps/desktop/src/services/socket.ts` 直接把 `localStorage.serverAddress` 喂给 socket.io。生产环境 web 用户登录时服务器地址填 `/api`（同源 nginx 代理路径），HTTP 请求 OK，但 socket.io 拿到相对路径 `/api` 无法解析 → WS 永远连不上 → 流转失败。mobile/hm 存的是绝对 URL 所以正常。
- 修复：socket.ts 第 31-46 行加判断——web 模式下 `serverAddress` 以 `/` 开头时强制回落 `window.location.origin`（nginx 已代理 `/socket.io/`）；同时在 connect 前加一行日志打出实际 URL 方便排查。

## 在线设备列表包含自己修复
- 根因：desktop `Player/index.tsx` 和 mobile `app/player.tsx` 过滤条件用 `d.deviceId !== (device?.deviceId ?? "")`，`device` 是登录接口返回的对象，老登录路径（LoginModal）或旧 localStorage 缓存里可能没 `deviceId` 字段 → 兜底空串 → 过滤失效 → 自己也显示在列表里。
- 修复：改用各端自己的 `getOrCreateDeviceId()` 作为过滤基准（localStorage/AsyncStorage 里的稳定 UUID，不依赖后端返回）。desktop 在组件内直接调用，mobile 用 useState + useEffect 异步加载。hm 端本来就是对的（`selfDeviceId` state）。

## 流转时目标端自动切换内容模式（音乐/有声书）
- 问题：流转音乐到目标端时，目标端如果当前在有声书模式，会在错误模式下播放（反之亦然）。
- 修复：三端 `transfer_received` handler 里，播放前根据曲目的 `type`/`contentType` 切换到对应内容模式。
  - **desktop** `Player/index.tsx`：`setPlayMode(targetMode)` + `store.syncActiveMode(targetMode)`
  - **mobile** `player.tsx`：新增 `switchContentModeForIncomingTrack` 暴露到 PlayerContext，流转接收端通过 ref 调用（避免闭包旧值）
  - **hm** `PlayerPage.ets`：`AppStorage.setOrCreate('playMode', targetMode)` + `kvStore.set` + `playerStore.switchContentMode(targetMode)`
- 修复：直接从 `.github/workflows/feat-test-release.yml` 和 `android-release.yml` 移除 `android-actions/setup-android@v3` step，改为一段 `Verify Android SDK` 输出 ANDROID_HOME 的调试命令。ubuntu-latest 镜像自带完整 Android SDK，无需 setup action。

## 任务中心轮询风暴修复（desktop/mobile/mini 三端）
- 问题：三端 TaskCenter 都 `setInterval(fetchTasks, 2000)` 无条件 2s 轮询，任务中心打开期间接口被打爆。
- hm 端任务中心未实现（PersonalPage 提示"暂未接入"），无需处理。
- 修复策略（三端统一）：
  - 有进行中任务（`isTaskActive`：pending/processing/paused）→ 2s 高频轮询
  - 无进行中任务 → 30s 慢轮询兜底（保证跨端发起的任务最终能被发现）
  - 用 `setTimeout` 递归调度替代 `setInterval`，每次根据最新任务列表决定下一次延迟
  - 手动刷新 / 暂停 / 恢复 / 删除后立即 `scheduleNext()` 重置计时
  - 用 `tasksRef` 同步最新列表避免闭包陷阱
- 涉及文件：
  - `apps/desktop/src/pages/TaskCenter/index.tsx`
  - `apps/mobile/app/task-center.tsx`
  - `apps/mini/src/pages/task-center/index.tsx`
