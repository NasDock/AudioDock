## desktop ArtistDetail 报 Invalid hook call 修复
- 根因：`apps/desktop/src/pages/ArtistDetail/index.tsx` 在模块顶层（组件函数体外）调用了 `theme.useToken()` hook，模块加载时即执行 → React Invalid hook call。
- 修复：把 `const { token } = theme.useToken()` 挪进 `ArtistDetail` 组件函数体首行。`token` 仅用于分页 sentinel 的 `colorTextSecondary`。
- 排查：全项目 grep 确认其他 useToken 均在组件内，无同类问题。

- 根因：GitHub 把 `ubuntu-latest` 迁到 ubuntu-24.04，Google 已下线 sdkmanager 的 `tools` 包，v3 版 action 还在尝试安装它。

## desktop 生产环境无法流转修复
- 现象：本地开发 desktop → hm/mobile 正常；生产环境 desktop 无法流转（hm/mobile 互转正常）。
- 根因：`apps/desktop/src/services/socket.ts` 直接把 `localStorage.serverAddress` 喂给 socket.io。生产环境 web 用户登录时服务器地址填 `/api`（同源 nginx 代理路径），HTTP 请求 OK，但 socket.io 拿到相对路径 `/api` 无法解析 → WS 永远连不上 → 流转失败。mobile/hm 存的是绝对 URL 所以正常。
- 修复：socket.ts 第 31-46 行加判断——web 模式下 `serverAddress` 以 `/` 开头时强制回落 `window.location.origin`（nginx 已代理 `/socket.io/`）；同时在 connect 前加一行日志打出实际 URL 方便排查。

## 在线设备列表包含自己修复
- 根因：desktop `Player/index.tsx` 和 mobile `app/player.tsx` 过滤条件用 `d.deviceId !== (device?.deviceId ?? "")`，`device` 是登录接口返回的对象，老登录路径（LoginModal）或旧 localStorage 缓存里可能没 `deviceId` 字段 → 兜底空串 → 过滤失效 → 自己也显示在列表里。
- 修复：改用各端自己的 `getOrCreateDeviceId()` 作为过滤基准（localStorage/AsyncStorage 里的稳定 UUID，不依赖后端返回）。desktop 在组件内直接调用，mobile 用 useState + useEffect 异步加载。hm 端本来就是对的（`selfDeviceId` state）。

- 修复：直接从 `.github/workflows/feat-test-release.yml` 和 `android-release.yml` 移除 `android-actions/setup-android@v3` step，改为一段 `Verify Android SDK` 输出 ANDROID_HOME 的调试命令。ubuntu-latest 镜像自带完整 Android SDK，无需 setup action。

- 涉及文件：

  - `apps/mobile/app/task-center.tsx`

## 秒播优化第一批（hm / mobile / desktop 三端）
- 目标：把「点击 → 出声」延迟压到接近秒播，三端同步推进。
- **hm 端**：所有播放入口从「整队列串行 resolveTrackToPlayer + playTrackList」改为「先 resolve 用户点的这首并立即播放，其余曲目后台并行补齐队列」。核心改动：
  - `trackResolver.ets` 新增 `playQueueFast(queue, startIndex, isExternal)` 统一入口，内部先 `resolveTrackToPlayer(queue[idx])` 开播，再 `resolveRestParallel` 后台并行补齐。
  - `PlayerStore.ets` 新增 `replaceQueuePreservingCurrent(fullQueue, currentTrackId)`：后台解析完成后把队列从「单首占位」升级为「完整列表」，不打断当前播放；若用户在解析期间又点了别的歌则丢弃结果（竞态安全）。
  - 8 个入口（MainPage / AlbumDetailPage / ArtistDetailPage / LibraryPage / PersonalPage / PlaylistDetailPage / SearchPage / SquirrelAgent）从串行 for 循环换成一行 `playQueueFast`。
  - 构建验证通过（`hvigorw assembleHap`）。
- **mobile 端**：三件事一起改：
  - `PlayerContext.tsx` `setupPlayer` 增加缓冲参数：`minBuffer: 15`（默认 50s 过大，是起播慢主因）、`maxBuffer: 50`、`playBuffer: 2.5`、`backBuffer: 30`。
  - `SettingsContext.tsx` `cacheEnabled` 默认值从 `false` 改为 `true`（新装用户默认开启本地缓存；已持久化设置不受影响）。
  - 音乐曲目也走 `resolveTrackUri` 本地缓存分支（之前只有有声书走），但 `shouldDownload`（后台下载）仅 Wi-Fi 下开启，避免蜂窝流量偷跑。新增 `isWifiNetwork()` 工具函数（expo-network）。
  - 3 处改动点：`loadPlaybackState` 恢复队列、`playTrackList` 后台缓存升级、`playTrack` 单曲播放缓存升级。
- **desktop 端**：`Player/index.tsx` 增加隐藏 `<audio ref={preloadAudioRef} preload="auto" style={{display:'none'}}>`，当前曲目播放时用 `buildTrackPlaybackUrl` 预载播放列表中下一首的 URL，浏览器/CDN 建立连接并缓存首包，切歌时主 audio 换到相同 URL 若命中 HTTP 缓存则秒切。已在 vite build 中验证 3897 个模块全部 transform 成功（构建失败是沙箱对 `@tauri-apps/api` 的文件读取权限问题，与改动无关）。

## 秒播优化第二批（服务端 / hm / desktop）
- **服务端 `/track/stream/:id` 加 Cache-Control**：`services/api/src/controllers/track.ts` 普通音频文件分支（`res.sendFile`）加 `Cache-Control: public, max-age=86400`。ffmpeg 实时转码路径和 STRM 代理路径不加（前者内容每次重新生成，后者由上游决定）。`nest build` 通过。
- **hm 边播边缓存接线**：
  - `features/storage/FileCache.ets` 新增 `downloadAudioFromUrl(trackId, ext, url)`：用 `@ohos.net.http` 从 HTTP URL 直接下载到 `audio_cache` 目录，不写离线下载元数据（不出现在「已下载」列表），失败静默。与 `downloadAudio`（本地 fs.copyFile）互补。
  - `PlayerStore.ets` `loadCurrent` 播放成功后调用 `triggerCacheWhilePlaying(t)`：读 kvStore `cacheEnabled` 开关，仅远程 URL + 未缓存时触发后台下载。下次播放 `resolveTrackToPlayer` 命中 `fileCache.hasAudio` 走 fdSrc 本地文件秒播。
  - `hvigorw assembleHap` 通过。
- **desktop 音质 profile 缓存**：`services/trackQuality.ts` `getTrackAudioQualityProfile` 加 `cacheUtils` 5 分钟缓存，key 为 `quality_profile_${trackId}`，避免同一首歌反复切换时重复请求 `/track/:id/playback-qualities`。esbuild 语法检查通过。
