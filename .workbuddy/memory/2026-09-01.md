## mobile iOS 模拟器 EXC_BAD_ACCESS（removeClippedSubviews / Fabric）

- 现象：iOS 模拟器打开/进入播放列表页崩溃，SIGSEGV / KERN_INVALID_ADDRESS。
- 栈：`updateClippedSubviewsWithClipRect:relativeToView:` 递归 → `convertRect:toView:` → `objc_retainAutoreleasedReturnValue` 野指针（0x2000000000003f00）。
- 根因：`apps/mobile/app/playlist/[id].tsx` 的 FlatList 显式开了 `removeClippedSubviews`（缩写=true）。RN 0.81 新架构(Fabric)下该优化有 bug，会把子视图摘出层级后 remount 时引用已释放 view 崩溃。RN 0.81 iOS 上 `removeClippedSubviews` 默认已是 false（`shouldUseRemoveClippedSubviewsAsDefaultOnIOS` 默认 false），全仓库仅此一处显式开启。
- 修复：改为 `removeClippedSubviews={false}` 并注释说明。长列表节点优化靠已有的 windowSize/initialNumToRender/maxToRenderPerBatch 即可。
- 注意：这是与 8/31 的「Hermes HadesGC 段错误（需重跑 pod install）」不同的第二个崩溃源，两者都要处理。

## feat-test 流水线 Tauri 插件版本不匹配（CI 报错）

- 现象：`tauri build` 阶段报 `tauri-plugin-http (v2.5.9) : @tauri-apps/plugin-http (v2.6.0)` 版本 mismatch。
- 根因：`apps/desktop/package.json` 里 6 个 tauri 插件 NPM 包都写宽约束 `^2.0.0`，CI 的 `pnpm install`（不带 `--frozen-lockfile`）重新解析时把 http 拉到最新 2.6.0；而 Rust 侧 `Cargo.lock` 锁的是 crate 2.5.9，minor（5.9 vs 6.0）不一致触发 Tauri 校验失败。
- 修复：把 `apps/desktop/package.json` + `pnpm-lock.yaml`（desktop importer specifier）里 6 个插件全部 pin 到与 `Cargo.lock` crate 一致的精确版本：autostart 2.5.1 / dialog 2.7.1 / fs 2.5.1 / http 2.5.9 / os 2.3.2 / shell 2.3.5。
- 注意：`@tauri-apps/api`/`@tauri-apps/cli`（^2.0.0）不在 mismatch 检查范围，未 pin；`tauri-plugin-opener` 仅 Rust 侧（Cargo.toml），NPM 侧无对应包，无需处理。

## hm 桌面小部件（2026-09-01 新增，对齐 iOS 4 种 widget）

- **构建验证**：`hvigorw --mode module -p product=default -p module=entry@default assembleHap --no-daemon` BUILD SUCCESSFUL（runtime SDK API 24 = HarmonyOS 6.1.1，兼容 SDK 9+）。
- **FormExtensionAbility import 路径**：API 24 用 `@ohos.app.form.FormExtensionAbility`（不是 `@kit.AbilityKit`/`@kit.FormKit`），formBindingData/formProvider/formInfo 都走同 prefix。
- **`postCardAction` 是全局函数**（在 `common.d.ts`），直接调用 `postCardAction(this, { action: 'message', params: { message: 'play' } })`，不需要 import。
- **`postCardAction` 三种 action**：
  - `'message'`（action 名 → onFormEvent(message: string)）+ 带 id 用紧凑 `'play_track:trackId'` 格式（EntryFormAbility 用 `:` 分隔拆 action/id）
  - `'router'` 拉起 UIAbility（widget 点击拉主 App）
  - `'call'` 拉起 UIAbility + 直接调 callee（高级用法，本次没用）
- **FormExtensionAbility 回调必须同步签名**：onAddForm 同步返回 formBindingData.FormBindingData，onUpdateForm/onFormEvent 同步 void。async 逻辑 fire-and-forget：`onAddForm(want) { this.asyncLoad().catch(...); return formBindingData.createFormBindingData(empty); }`。
- **FormInfo 没有 formId 字段**（API 24）：getFormsInfo() 返回的 FormInfo 只有 bundleName/moduleName/abilityName/name/defaultDimension 等。所以 formName → formId 映射必须由 EntryFormAbility.onAddForm 主动写入 kvStore `widget_form_ids_${formName}`。WidgetBridge 推数据时从 kvStore 读映射逐条 updateForm。
- **form_config.json 字段约束**：supportDimensions 必须是允许值（`'1*2','2*2','2*4','4*4','1*1','6*4','2*3','3*3'`），**没有 '4*2'**！scheduledUpdateTime 必须是 HH:MM 单点（如 "00:00"），不是区间。
- **defaultDimension 字符串 vs 数字**：form_config.json 用 "2*2" 字符串；getFormsInfo() 返回的 FormInfo.defaultDimension 是 FormDimension 枚举 number（2=2x2, 3=2x4, 4=4x4）。
- **ArkTS 严格模式坑**：
  - 不用 `as const`，改 class + static readonly 字段
  - 不用对象字面量当类型（Record<string, ...> 也不行），先 `const x: Record = {}; x['key'] = val` 两步赋值
  - 不用 `NowPlayingSnapshot['field']` indexed access type，要先 typedef
  - 不用 `Class.field[key]` 索引访问字段，改 if/switch
  - 不用 `Row().fill()` 改 `Row().backgroundColor()`
  - `@Entry` 缺 `()` 参数（仅 WARN，不影响构建）
  - `@Builder` 函数体内不能用 const/if，要 UI 组件直接堆叠
  - `FontWeight.SemiBold` 不存在，改 `FontWeight.Medium`
- **PreferencesStore.init 签名**：从 `common.UIAbilityContext` 改为 `common.Context`（基类），让 FormExtensionAbility 也能复用（getApplicationContext() 不是 UIAbilityContext）。同 HAP 共享 preferences storeName = 'audiodock_kv'。
- **postCardAction 调主 App 拉起**：用 `action: 'router', abilityName: 'EntryAbility', params: { url: 'audiodock://player' }`。EntryAbility.handleWidgetDeepLink 解析 uri 并 router.pushUrl 到目标页（已加 audiodock scheme 到 skills.uris）。
- **会员锁定页（已集成）**：`EntryFormAbility.readIsLocked()` 读 kvStore `widget_vip`，未命中回落到 `plusApi.getVipStatus(plus_user_id)`（需 ensureKvAndHttpReady 同步设 plusToken）。`loadSnapshotForKind` 写入 `out['isLocked'] = true` 时 short-circuit 返回（不拉歌单/历史/上新），4 张卡片组件 `@LocalStorageProp('isLocked')` + `if (isLocked) LockedCard()` 分支。LockedCard 走 `postCardAction('router', 'audiodock://member-benefits')` 拉起主 App 会员页。

## hm 桌面小部件卡片背景修复（黄色锁定页 bug，2026-09-01 晚）

- **现象**：4 张卡片全部显示 LockedCard（浅金色皇冠 `#FFD980` + 白色字体 ≈ 用户说的"黄色背景+白色字体"），且所有 4 张背景都是默认深紫蓝渐变，没有 iOS 的封面+磨砂玻璃效果。
- **根因 1（VIP 误锁定）**：`EntryAbility.initialize()` 和 `EntryFormAbility.ensureKvAndHttpReady()` 都**没调** `authStore.loadFromStorage()`，导致进程内 `authStore.state_.user?.id` 永远是 null；`WidgetBridge.syncVip()` 用 user.id（**且 mobile 端用的是 `plus_user_id`** 不是 user.id），未登录时把 `isVip: false, updatedAt: Date.now()` 写进 KV；`EntryFormAbility.readIsLocked()` 看到 `cached.updatedAt > 0` 就直接判定非会员 → 全部锁定。
- **根因 2（没磨砂玻璃）**：`WidgetBackground.ets` 没对封面 Image 用 `.blur()`（iOS 是 `.blur(radius: 18)`），且 PlaylistCard / LatestCard 没用 WidgetBackground，root Column 写死 `.backgroundColor('#1a1a2e')`。
- **修复**：
  - `EntryAbility.initialize()` 末尾加 `await authStore.loadFromStorage()`（主 App 进程 user 恢复）
  - `EntryFormAbility.ensureKvAndHttpReady()` 加 `await authStore.loadFromStorage()`（卡片进程 user 恢复）
  - `WidgetBridge.syncVip()` 改用 `kvStore.get('plus_user_id')`（对齐 mobile `syncVipState`），未登录时**不写 KV**（避免下次读 KV 误判）
  - `WidgetBackground.ets` 给封面 Image 加 `.blur(20)`（对齐 iOS `blur(radius: 18)`，hm Image.blur 支持任意 number）
  - `PlaylistCard.ets` / `LatestCard.ets` 改用 `Stack() → WidgetBackground({ cover: firstCover(), ... })`，root 不再写死 `#1a1a2e`，封面来自首张歌单/首张新歌
- **教训**：跨进程 KV 共享时，单例 store（AuthStore）必须在进程启动时显式 `loadFromStorage()`，不能依赖"主进程已经写过 KV"——卡片进程是独立 process，主进程的内存状态完全不可见。
