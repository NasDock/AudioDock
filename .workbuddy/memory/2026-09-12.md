## 修复：有声书播放 404

- 现象：有声书 `GET /audio/鬼吹灯/xxx.mp3` 404，音乐正常
- 根因：有声书播放走 `apps/mobile/src/services/trackResolver.ts` 的 `resolveTrackUri`，把非 http 的 `track.path`（`/audio/...`）直接拼 baseURL 请求裸路径；后端 `main.ts` 只挂了 `/covers/`、`/music/` 两个静态目录，**没有 `/audio/` 静态服务** → 落 Nest 路由报 `Cannot GET /audio/...`。音乐正常是因为走 `player.tsx:696` 的 `/track/stream/:id` 接口（`getFilePath` 把 `/music/...` 映射到磁盘）。
- 修复（用户选后端挂静态服务方案）：`services/api/src/main.ts` 在 `/music/` 挂载后新增 `/audio/` 静态服务，循环挂 `audiobookDirs`（支持多目录，Express 静态 miss 自动 fallthrough），setHeaders 加 `Accept-Ranges: bytes` + 各音频格式 Content-Type（有声书拖进度条必须支持 Range）。
- 注意：`resolveTrackUri` 仅 AUDIOBOOK 分支调用，music 不受影响；裸 path 访问是直连不代理（外网/strm 场景与 stream 接口行为不一致，属已知取舍，STRM 重构后统一走 stream 会自然消除）。
- 验证：tsc --noEmit 通过（+21 行）。本地 music/audio 无"鬼吹灯"目录（404 发生在部署环境 AUDIO_BOOK_DIR=/audio），无法在本地起服务实测 200，但改动与 `/covers/`、`/music/` 两处生产在用的 useStaticAssets 完全同构。

## 修复：mobile 版本更新弹窗点击「立即更新」后不自动关闭

- 现象：发现新版本后点「立即更新」（或「前往应用商店」）按钮，弹窗不自动关闭
- 根因：`apps/mobile/hooks/useCheckUpdate.ts` 的 `startUpdate` finally 中只重置 `opening=false`，**没清空 `updateInfo`**：
  - 商店模式：`openStoreByPlatform()` 跳完商店回到 App，`updateInfo` 还在 → 弹窗仍在
  - 小米模式：`downloadAndInstallApk()` 提交任务后 `opening=false` → `UpdateModal` 里 `isDownloading = opening && mode==='xiaomi'` 变 false，弹窗从下载视图切回按钮视图，**看起来像弹窗没关**
- 修复：进入 `startUpdate` 立刻 `setState({opening:true, updateInfo:null, progress:0})` 关闭弹窗；只有跳商店/创建下载任务失败时 `setState({updateInfo:info})` 恢复弹窗让用户重试或忽略。Alert 用全局 Alert，弹窗关闭不影响报错
- 修改文件：`apps/mobile/hooks/useCheckUpdate.ts`（仅 `startUpdate`，+14/-6 行）；`_layout.tsx` 和 `settings.tsx` 的两个 UpdateModal 实例共享同一 hook，自动生效
