## hm 歌词页「轻点 vs 拖动」修复
- 现象：竖屏 / 车机歌词页点一下歌词，弹出中心行时间戳 + 播放按钮（用户说的「触发滚动时间」），却不切回封面。
- 根因：上一轮把 `onTouch(TouchType.Down)` 直接当拖动信号 → `beginLyricInteract()` 立刻置 `lyricInteractingRef=true`，既渲染了中心操作条，又被 `onLyricsBackgroundClick()` 里的 `if (lyricInteractingRef) return` 挡掉了切封面。
- 修复（`PlayerPage.ets` + `EmbeddedPlayerPanel.ets` 同构）：
  - 新增 `lyricTouchStartY / lyricTouchingRef / lyricDragActiveRef / lyricDragEndAt`，抽出 `handleLyricTouch(event)`：Down 只记起点，Move 位移 >8vp 才 `beginLyricInteract()`；Up/Cancel 记拖动结束时间戳。
  - `onScrollIndex` 加兜底：手指仍按着且列表确实滚动（Move 被 List 手势吞掉）时补一次接管；程序化滚动因 `lyricTouchingRef=false` 不会误触发。
  - 点击处理不再被 `lyricInteractingRef` 拦：轻点始终切回封面（横屏歌词常驻不切），并 `resetLyricInteraction()` 清 2s timer + `lastLyricIndex=-1`（下次进歌词重新居中当前行）；拖动抬手 400ms、点播放按钮冒泡 400ms 的时间戳 guard 保留。
  - `resetLyricInteraction()` 顺带清 touch refs（切歌 / 卸载无残留）。
