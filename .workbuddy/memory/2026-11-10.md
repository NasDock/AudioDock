## 飞牛音乐（fnOS trim.music）API 调研 → docs/fnos-music-api.md
- 目标：把 NAS（mmdctjj.fnos.net）上的飞牛音乐作为 AudioDock 第三种外部源（对齐 adapter/emby、adapter/subsonic）。
- 网关：`/music/api/v1`；局域网 `http://<NAS>:5666/music/api/v1`，远程 `https://<fnid>.fnos.net/music/api/v1`。
- 信封 `{code,msg,data}`；`code===120001` = 会话失效；`X-Music-API: v1` 头（登录类接口除外）；新版前端另有 `authx` 逐请求签名（时间戳+nonce）。
- 实测（登录态浏览器直连 URL）：`/initialization/state`、`/user/me`、`/track/list`、`/album/list`、`/album/detail`、`/artist/list`、`/playlist/list`、`/track/album-detail/list`、`/search/track`、`/play-history/list`、`/favorite-track/list` 全部 code 0。
- 关键结论：纯 JSON 接口**只靠 Cookie 会话即可**（无需 authx）；但 `/static/cover`、`/track/stream` 缺签名返回 **HTTP 400** → 媒体必须服务端代理（注入签名 + 透传 Range）。
- 分页契约：`page`(1起)/`size`(`-1`=全部)/`sort="<field>,<asc|desc>"`；响应回显 `data.sort`；**无 hasMore**，只能靠 total 算。搜索接口有「越界回钳第 1 页」「忽略 size 全量返回」两个坑。
- 参数命名：专辑曲目用 `albumGUID`、歌单曲目 `playlistGUID`、搜索关键词 `q`、收藏写 `{trackGUID}`、歌单加歌 `{guid, trackGUIDs:[]}`、历史删除 `{trackGUIDs:[]}`、播放上报 `{events:[{eventType:"track_play",payload:{trackGUID}}]}`。
- TrackVO 关键字段：guid/title/coverId/year/discNo/trackNo/isCue/duration(ms)/album{}/artists[]/genres[]/audioSpec{bitDepth,sampleRate,channel,bitrate,codec,container,duration,format,path}/size/isFavorite；搜索条目额外带 `score`。
- 踩坑：Chrome 里读 JSON 只能靠截图，宽表格要 `clip` + 缩放 + `data.sort` 自检；本机 Chrome 缓存里抓不到前端 bundle（存的是压缩后的 encoded body）。
- 待确认：authx 算法（用户说登录逻辑后面由别人提供）、`/lyric/list` 返回形态、`/playlist/{action}` 的 action 名、`/folder-view/list` 与 `/genre/list` 真实路径、size 上限。

## 飞牛登录协议落地（晚，参考 QiaoKes/fn-music-tv 的 TrimMusicApi/ConnectionAccess）
- **authx 是误判**：它只用于 FN Connect 的 fnId 解析（`https://5ddd.com/api/v1/fn/con`，`FnConnectSigner.authx()`，需内嵌 AES 密钥）。音乐业务接口**不需要任何签名**。之前记的「媒体缺签名 400」应更正为「媒体缺 Authorization 头 → 401」。
- 鉴权真相：`Authorization: <userToken>`（**无 Bearer 前缀**）；token 字段叫 `data.userToken`；登录 body `{username, password: sha256hex(明文), deviceId}`，**不能带 `X-Music-API` 版本头**；登录前先 `GET /sys/config`（免登录）做预检拿 serverName/serverGUID。
- 错误码：99999 无效 token（HTTP 401）、120001 会话失效 / **登录时=账号密码错误**、120002 账号禁用、100004 曲目不可用、100005 不存在 → 必须按流程区分 120001 语义。
- FN Connect 中继（`*.fnos.net` / `*.5ddd.com`）每个请求都要 `Cookie: mode=relay`（带 token 再加 `music-token`），否则 302 到登录页；`Cookie` 是浏览器禁止头，只有 Rust 侧能发。
- **飞牛网关零 CORS 头**（OPTIONS 直接回 SPA HTML）→ desktop 必须用 `@tauri-apps/plugin-http` 的 fetch 走 Rust；已加 `setFnosTransport()` 注入点 + `apps/desktop/src/services/fnosTransport.ts`（web 构建自动跳过）。媒体 `?token=`/`Cookie music-token` 全部 401，只认 Authorization 头 → 封面/音频须 `fetchMediaObjectUrl()` 或服务端反代（Range 透传）。
- 地址归一化：裸中继域名走 https:443，裸 IP/主机名走 http:5666，显式 `http://` 走 80；顺带剥掉 `/music`、`/api/v1`、`/music/api/v1` 尾巴。
- 传输层可注入也让 Node 单测可行（本机 Node 不认 HTTP_PROXY，冒烟时用 curl 当 transport 打通真机接口）。

## 飞牛登录「请求没到服务器」三处真因（排查结论）
- **Tauri plugin-http scope 默认为空**：capability 里只写 `"http:default"` 不配 allow 列表 → Rust 侧直接返回 `url not allowed on the configured scope`，请求一个字节都出不了网卡（devtools Network 也看不到，因为走 IPC 不经浏览器网络栈）。
- **URLPattern 端口是独立分量**：`http://*` **不匹配** `http://192.168.1.10:5666/...`；实测 urlpattern 0.3 覆盖矩阵：`http://*` 只覆盖无端口、`http://*:*` 覆盖有端口、`*://*` 不覆盖有端口、`*://*:*` 全覆盖。capability 必须同时写 `http://*` / `http://*:*` / `https://*` / `https://*:*` 四条。
- **`Cookie: mode=relay` 会被插件静默丢弃**：plugin-http 按 fetch 规范过滤 forbidden header（Cookie 在内）→ 中继域名必 302 到登录页。必须 `tauri-plugin-http = { version = "2", features = ["unsafe-headers"] }`。
- **`crypto.subtle` 只在安全上下文可用**：用 `http://192.168.x:5199` 开 dev server 时 subtle 为 undefined，密码 hash 抛错恰好卡在「预检成功 → 发登录」之间，表现就是只看到 `/sys/config`、登录 POST 没发出。`sha256Hex` 已内置纯 JS 兜底（已用 shasum 对 ASCII/中文/空串逐一校验）。
- 排查口诀：登录是 `GET /sys/config`（预检）→ `POST /user/password-login`（真登录）。只看到前者就是链路断开，不是接口选错。`client.send()` 现在会打印 `[Fnos] → / ← / ✗`。

## 飞牛登录的权威实现（kunjingdi/fn-music-player，Electron，实测可用）
- 仓库 <https://github.com/kunjingdi/fn-music-player>：`server.cjs` 里有完整登录+签名，`electron-main.js` 只是窗口/全屏。渲染层走 `fnm://srv` 自定义协议 → 主进程代理到 NAS 并注入 authx + `music-token`。
- **登录**：`POST /music/api/v1/user/password-login`，body `{username, password: sha256hex(明文), deviceId: 32位小写hex}`；头 `Accept/Accept-Language: zh-CN/Content-Type/User-Agent/authx`，**没有 X-Music-API**。成功判据 `code===0 && data.userToken`。
- **会话**：`Cookie: music-token=<encodeURIComponent(token)>`（不是 Authorization）；媒体接口同头 + 透传 Range；99999 → 静默重登一次（并发共享 promise）再重试。
- **authx（MD5，非 HMAC）**：`nonce=6位随机&timestamp=毫秒&sign=md5([AUTHX_PREFIX,pathname,nonce,ts,payloadHash,CLIENT_KEY].join("_"))`；GET 的 payloadHash = md5(decodeURIComponent(canonicalQuery))（canonicalQuery = key 排序 + URLSearchParams + `+`→`%20`），POST 的 = md5(body 原文)；pathname 必须含 `/music/api/v1`。
- **两个常量** `authxPrefix`/`clientKey` 仓库只给占位（config.local.example.json），安装包里内置。**实测 1.1.19 服务端不校验 authx**（伪造/缺失都回同样结果），所以没有常量也能登录。
- 坑：`/static/cover` 只认 `album_/track_/artist_` 前缀的 coverId，歌单详情会塞裸 32 位 hex（实为曲目 GUID）→ 400；歌单封面取第一首有封面的歌。
- 已落地到 AudioDock：`fnos/hash.ts`（纯 JS md5+sha256）、`fnos/auth.ts`（buildFnosAuthx/createFnosAuthxSigner/setFnosAuthKeys）、client 改 Cookie+Accept-Language+deviceId 归一化 32hex、lyric 改 trackGUID、coverId 清洗。md5/authx/deviceId 已与 server.cjs 逐字节对拍通过。

## 飞牛 web 端跑通（客户端链路定稿）
- **web 走 vite dev 代理**：`apps/desktop/vite-plugin-fnos-proxy.ts` 挂 `/__fnos` 前缀。浏览器发同源请求 → dev server 代转到 NAS 并补 `Cookie: mode=relay; music-token=…`。目标地址用 `?__b=<origin>` 传，token 由代理按 origin 记住（**不写进 URL**，否则会被应用把那整条地址缓存进 localStorage，重新登录后 token 变了全 401）。
- **Tauri 走自定义命令** `fnos_request`（`src-tauri/src/fnos_http.rs`，reqwest，`redirect=Policy::none`）。放弃 `tauri-plugin-http`：scope 默认为空（要写 4 条 URLPattern，端口是独立分量）+ 按 fetch 规范过滤 Cookie，两个坑都让请求「根本没出网卡且 devtools 看不到」。
- **媒体**：`setFnosMediaProxy("<origin>/__fnos")` 之后 `getCoverUrl()/getStreamUrl()` 直接返回代理地址，`<img>/<audio>` 可用；实测封面 `200 image/jpeg 640x640`、音频 `206 audio/mpeg` 且 Range 正常。
- **播放地址坑**：`buildTrackPlaybackUrl()` 原本无脑拼 `{AudioDock 服务端}/track/stream/{id}`，外部源 id 它不认识 → 必 404。已加分支：第三方源直接返回 `track.path`，且**不能追加 `?quality=`**（这些地址自带 query）。
- 前端 `soundx_cache_*`（localStorage，5 分钟 TTL）会缓存 cover/path，改了地址口径要清一下。
- 待办：桌面端媒体鉴权（`<img>/<audio>` 加不了请求头）→ 下一步做 `fnos://` 自定义协议（参考 `protocol::handle_media`）。

## 桌面端（Tauri）飞牛封面/播放修复：本地 /fnos 转发
- 根因：`fnosTransport.ts` 的 Tauri 分支**从未调用 setFnosMediaProxy**，`getCoverUrl()/getStreamUrl()` 返回直连 `https://<host>/music/api/v1/static/cover|track/stream`，`<img>/<audio>` 带不上 Cookie → 401，封面全空。
- 方案：复用已有本地回环媒体服务器（`media_server.rs`，axum，AVPlayer 只认 http），新增 `src-tauri/src/fnos_media.rs`：
  - 路由 `GET /fnos/{*rel}?…&__b=<上游origin>`；`__b` 由前端 buildMediaUrl 拼入，转发前从 query 摘掉；补 `Cookie`（按 origin 存的会话），透传 `Range`，`bytes_stream()` 流式回灌。
  - 会话表 `FnosSessions = Arc<Mutex<HashMap<origin, cookie>>>`；命令 `fnos_set_media_session(origin, cookie)` 由前端同步（去重 + await 保序）。
  - 校验：`__b` 必须 http(s) 且**已在会话表里**，否则 403（回环端口任意本地页面可见，不能让别人借 Cookie 读账号）。
  - `media_server::start(download_path, fnos_sessions)` 加 `.route("/fnos/{*rel}")` + `FromRef<MediaState> for FnosSessions` 子状态提取。
- 前端：`fnosTransport.ts` 新增 `mediaProxyReady` promise（`initMediaProxy` 取 `get_media_origin` → `setFnosMediaProxy(${origin}/fnos)`，失败退避重试 3 次），`tauriTransport` 先 await 它再 await `syncMediaSession`，因此**媒体地址生成时前缀与会话必定就绪**。端口每启动随机 → 设好代理后 `cacheUtils.clearAll()` 清掉带旧端口的 `soundx_cache_*`。
- 实测（macOS dev 实例）：`curl 127.0.0.1:<port>/fnos/.../static/cover?coverId=track_…&size=300&__b=…` → 200 image/jpeg 640×640；`-r 0-2047` 音频 → 206 audio/mpeg + content-range 0-2047/1147868；未同步 origin → 403；WKWebView（com.apple.WebKit.Networking）对本地端口保持 5 条长连接 = 封面在走代理。
- 注意：`cargo check`/tsc 均通过；tauri dev 启动用 `npx tauri dev --no-dev-server-wait -c '{"build":{"beforeDevCommand":""}}'` 复用已开的 5173，避免 strictPort 冲突。

## 飞牛源自动切音乐模式
- 问题：`playMode`（localStorage `playMode`，值 MUSIC/AUDIOBOOK）上次在官方源听有声书时会残留 audiobook；飞牛曲目 type 恒为 MUSIC，桌面端列表/听过/收藏都按 type 过滤 → 进飞牛后全空。

## 飞牛歌词接入（歌词必须懒加载）
- 接口实测：`GET /music/api/v1/lyric/list?trackGUID=<曲目guid>` → `{list:[{guid,source,content,isLRC,offset}], preferred}`；`content` 是 LRC 文本；**只认 `trackGUID`**，`guid` 已无效；无歌词时 `list:[]`。老版本还会返回 LRC 数组形态，已不再出现。
- 关键事实：**TrackVO 里没有歌词**（`/track/list`、专辑/歌手/歌单曲目都不带），官方前端也是播放时才单曲拉。所以不能指望 mapper 一次性带出。
- `mapper.extractLyricText` 重写：优先 `list` 里 `guid === preferred` 那条，再退回第一条非空；兼容 `{content}`、`{lyric}`、纯字符串；空串/纯空白视为无歌词。已用浏览器实测四种形态。
- `track.getLyrics` 去掉了「无歌词就再打一次 `guid`」的重复请求，只在请求 throw 时才回退。
- desktop：`components/Player/index.tsx` 新增歌词懒加载 effect（`isFnosSource()` + `currentTrack.lyrics` 为空才调 `getTrackLyrics(id)`），结果存 `fetchedLyrics {id,text}` 并按 track id 校验，避免切歌串词；`currentLyrics` 派生出后同时喂给解析 effect 和两处 `<Lyrics>`。mini 窗口 / 独立歌词窗口本来只吃 Player 发出的 `lyric:update` 事件，无需改动。
- 验证（web 5173，飞牛源）：播放「愿一天有人这样唱给我」→ `/lyric/list` 200，全屏播放器歌词整篇显示、当前行加粗高亮随进度推进。services tsc + father build（81 files）、desktop tsc 全通过。
