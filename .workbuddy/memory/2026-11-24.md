## 合入 master + 修复 mobile 电台模式"几首后卡加载中"
- 合并 `origin/master` 到 `feat/test`（merge 提交 `55aede47`，无冲突；master 只带入 skills 相关提交 9edcb259）。
- 现象：电台模式听几首歌后播放器永久"加载中"，需重进 app；普通列表模式正常。
- 根因（`apps/mobile/src/context/PlayerContext.tsx`）：电台 `playTrack(...,fromRadio=true)` 走"add → skip(旧队列长度) → fire-and-forget remove(旧快照索引)"。`remove` 用旧长度算索引且吞错误，并发切歌（QueueEnded/PlaybackError/用户点 next）时索引越界被原生整体拒绝或删到刚 add 的 active track → 队列残留/active 丢失 → 原生卡 Buffering/Loading；`isLoading` 唯一写点在 PlaybackState 事件、无超时自愈。逐首累积→"几首后才坏"；重进 app 走 loadPlaybackState 的 setQueue 重建→恢复；普通模式用 playTrackList 整列 setQueue + skipToNext，不走这段→不受影响。
- 修复（仅改 PlayerContext.tsx，+76/-15）：
  1. 电台 `playTrack` 改用 `setQueue([trackData]) + skip(0)` 单曲重建，绕开 add/skip/remove（queue 快照改为函数级 let，普通模式逻辑不变）；
  2. `playNext` 电台分支加串行锁 `radioAdvanceInFlightRef`（finally 释放）+ 失败时清 loading；
  3. PlaybackState 里加 12s loading watchdog（仅电台）：卡 Buffering/Loading 无后续事件时用当前曲目 forceReload 重建，无当前曲则 playNext；退出电台清预载/loading/watchdog。
- 验证：`npx tsc --noEmit -p apps/mobile/tsconfig.json` 中 PlayerContext.tsx 无错误（其余为仓库既有错误：artist/[id].tsx、member-benefits.tsx、webdav-sources.tsx、SkeletonBlock.tsx、networkUtils.ts、packages/services 等）。
- 参考线索：远程分支 `codex/fix-playback-issue-after-several-songs` 的旧提交 450892cc 修的是普通模式队列边界 skipToNext（已合入主线 L1494-1503），非本次根因。

## 三端排查结论（均无 mobile 同类根因）
- **desktop**：有电台模式，但底层是单个 HTML `<audio>` 换 src、zustand 整列替换 playlist，无原生多曲队列 add/skip/remove → 不适用。次要隐患（非同类）：`<audio>` 未绑 onError/onStalled、isLoading 无 watchdog、电台 next() 无串行锁，属所有模式共有的加载兜底缺失。
- **hm**：有简化电台模式，JS 数组单曲重建 + 单 AVPlayer load（stop/reset 后设新源），且 load 内置 15s prepare 超时；电台实际不自动连播随机曲（queue 仅 1 首，SEQUENCE 下 computeNextIndex 返回 -1）→ 不适用。
- **mini**：未实现电台模式（全文搜索无命中，`Radio` 仅为 Taro UI 单选组件），用 BackgroundAudioManager.src 单实例替换 → 不适用。
- 本次未改 desktop/hm/mini（用户偏好聚焦、改动最小化）。

## desktop/mobile 封面"先复用列表小图占位、再升级高清"消除黑屏
- 现象：点播放列表后 mini + 详情页封面重新加载，期间黑屏。
- 根因：列表/mini/详情页封面 URL 档位不同（desktop 列表 w=96、mini 128、详情 600/q80；mobile 列表 96、mini 96、详情 900），目标大图下载慢期间无图。两端档位由 `bucketWidth` 量化，占位用与列表**同参数**即可命中缓存。
- 方案：渐进式封面——低档占位（列表已加载→缓存秒开）先显示，后台预载高清后替换。
  - desktop：改造 `components/LazyImage` 加 `placeholderSrc` prop（初值=占位；切歌用 useLayoutEffect 同步重置避免闪旧图；预载触发键改 src 避免重复请求；预载失败保留占位）；`Player/index.tsx` 加 `coverPlaceholderUri`（width:60→w96）传大封面+底部条；`MiniPlayer` 主封面传 width:60 占位。
  - mobile：新增 `components/ProgressiveImage.tsx`（显示层始终有图；普通源用 `Image.prefetch`，带 headers 飞牛源用隐藏 Image onLoad 兜底；切歌判定键 = 占位uri+高清uri，回调校验防旧图覆盖；隐藏 Image 加 key={targetUri}）；`player.tsx` 两处主封面（竖/横 square）+ 两处 VinylCover 传 96 档占位；`VinylCover` 加 `placeholderUri` prop 内部换 ProgressiveImage；`MiniPlayer` 换 ProgressiveImage（占位 96、source 128）。
- 验证：desktop tsc 全量 0 错误；mobile 改动文件无错误（9 个既有错误在别的文件）。经 agent code review 修复 S1 隐藏Image onLoad竞态、M1 切歌闪旧图、M2 内外网切换残留、M3 重复预载、L1 预载失败保留占位。
- 注意：外链封面（Emby/Subsonic/飞牛）getImageUrl/trackResolver 原样返回、与尺寸无关 → src===placeholder，不触发预载，无回归。
