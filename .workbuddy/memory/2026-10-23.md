## desktop 首页（Recommended）封面自适应缩小
- 需求：不改专辑/艺术家封面默认大小；空间能放 >4 个专辑（艺术家 >5）用现有算法，放不下时封面等比缩小，保证至少 4 专辑 / 5 艺术家。
- 改动 `apps/desktop/src/pages/Recommended/index.tsx`：
  - 抽出 `getAvailableWidth()`（含车机模式扣宽逻辑），新增 `getSectionLayout(type)` 返回 `{count, coverSize}`：fitCount >= minCount 用自然尺寸（专辑 170、艺术家头像 120、gap 24），否则 count=minCount、coverSize 等比缩小（下界 60px）。
  - `getPageSize` 改用 `getSectionLayout().count`；渲染处 Cover 传 `size={coverSize}`、Avatar 传 `size={coverSize}`，艺术家名加 `maxWidth: coverSize+24` + ellipsis。
- tsc --noEmit 通过。
- 修复缩放模式下最后一个卡片换行（两次迭代）：
  - ① 艺术家名字 maxWidth 从 coverSize+24 改为 coverSize（否则会撑宽卡片 24px）；缩放封面减 1px 亚像素容差。
  - ② 关键教训：**渲染期不能读 ref 算布局**——loadSections 先 setLoading(true) 切骨架屏会卸载容器，重新渲染内容时 ref.current 仍是 null（ref 提交阶段才挂载），回退 window.innerWidth 估算又被滚动条宽度坑。最终方案：根容器常驻不卸载（骨架屏改渲染在容器内部），宽度用 ResizeObserver 同步到 `containerWidth` state（clientWidth 不含纵向滚动条，且滚动条出现/消失也会触发），getAvailableWidth 只读 state，首次渲染才回退 window 估算。
- 缩放模式下拖宽度不再触发重新拉数据：新增 `fetchedSizeRef` 记录上次拉取的 album/artist/track 数量（loadSections 和 refreshSection 里同步），resize/车机栏宽变化的防抖回调先经 `shouldReloadForLayout()` 比较——数量没变（缩放模式数量固定 4/5，仅 coverSize 变）直接 return，由 containerWidth state 驱动封面缩放即可；数量变化（如窗口拉宽退出缩放模式）才 loadSections(true)。
