## 手机横屏封面轮播闪烁/空位修复（mobile player.tsx）

**症状**：切歌时旧封面闪回中心又跳走 / 下一首封面跳到中心又归位；或 ±1 槽位空一块不渲染。

**根因**（两症状是同一时序缺陷的两面）：
1. 旧方案 `coverFlowIndexAnim.setValue` + `coverFlowPanX.setValue` 是两次独立原生指令，不保证同帧生效——中间帧出现「旧封面回中心」或「下一首封面跳到中心」。
2. `setValue` 立即生效（位置已跳到新中心）而 `coverFlowVisualIndex` 是 React state（窗口/层级下一帧才渲染）——中间帧位置在新中心、渲染窗口还是旧范围 → +2 项没挂载（空位）、旧中心仍排最后渲染=盖在新封面上（闪回）。

**修复**（apps/mobile/app/player.tsx）：
- 合并双动画值为单个 `coverFlowPosAnim`（视觉中心的队列坐标，effPos = idx − posAnim）；切歌只是一次 `Animated.timing` 到目标，收尾无 setValue。
- **树先于位置**：snap 时先 `setCoverFlowVisualIndex(target)`（窗口/层级立刻切），动画经 `requestAnimationFrame` 延后到 React 提交后启动；外部切歌走 `useLayoutEffect` 先提交树再 `setValue` 跳位置。消除裸帧。
- 渲染窗口 ±2→±3，interpolate 扩到 ±3 且 opacity 归零——±3 是缓冲槽，窗口 state 落后 1 位时 ±2 仍有挂载节点。
- CoverFlowItem 自定义 memo 比较只认 `track.id/track.cover/idx/posAnim`，防进度上报 map 重建 track 对象导致整排重渲染。
- placeholder 统一 `picsum.photos/seed/placeholder/300/300`（固定 seed，不再用随机图 `/400`）。

## 去掉封面假阴影层
用户反馈手机横屏封面周围有两圈半透明黑色背景——即 CoverFlowItem 内的 coverFlowShadowOuter/Inner 两层假阴影（rgba(0,0,0,0.20/0.16)）。已移除这两层 View 及样式，封面仅保留 borderRadius 圆角，不再有任何阴影/扩散层。

## 封面阴影方案统一
竖屏 artwork 用 `boxShadow: "0px 10px 20px rgba(0,0,0,0.3)"` + `elevation: 10`（Android 兜底）即可正常投影；横屏 coverFlowImage 原本无阴影导致视觉突兀。已给 coverFlowImage 加同款 boxShadow + elevation，与竖屏观感一致。结论：RN 0.76+ 的 boxShadow 是当前阴影正解，不需要假阴影层。

## 横屏轮播点击命中重写
原 handleCoverFlowTap 用硬编码 x 坐标分段（adx<=100 播停 / 100~144.4 相邻 / 144.4~166.7 跳2），未真正命中封面区域——左侧边界对不准，用户点相邻封面会跳到上上首。重写为按封面可见区域精确命中：
- 中心 |dx|<=100（200px 宽）→ 播放/暂停
- ±1 相邻 [100,144.45]（可见 1/3）→ snap ci±1
- ±2 最外 [144.45,166.65]（可见 1/3）→ snap ci±2
- >166.65 空白只唤回 chrome 不切歌

## Windows 任务栏缩略图定制（desktop / Tauri）

需求：鼠标悬停任务栏图标时，缩略图从「窗口实时预览」换成「当前歌曲封面」，下方加「上一首 / 播放暂停 / 下一首」按钮（WMP 形态）。

实现（`apps/desktop/src-tauri/src/taskbar_thumb.rs`，仅 windows target）：
- 按钮：ITaskbarList3::ThumbBarAddButtons（setup 时加一次，不可移除）；播放/暂停图标+tooltip 用 ThumbBarUpdateButtons 热更；点击走 WM_COMMAND（HIWORD=THBN_CLICKED 0x1800，LOWORD=按钮 id 101/102/103）→ emit player:prev/toggle/next。
- 封面：DWMWA_FORCE_ICONIC_REPRESENTATION 关实时预览 + WM_DWMSENDICONICTHUMBNAIL(0x0323) 里 DwmSetIconicThumbnail；Aero Peek 走 0x0326 + DwmSetIconicLivePreviewBitmap。位图 32bpp top-down BGRA，封面按比例居中合成在深色底（18,18,18）上。
- 封面数据：PlayerStateForTray 加 cover 字段（serde default），tray::update_player_state → taskbar_thumb::sync；前端 Player/index.tsx 三处 update_player_state 传 `resolveArtworkUri(currentTrack,{width:300})`。Rust 侧 http(s) 走 reqwest（10s 超时），media:// 按 protocol.rs 规则读本地；加载代数防切歌覆盖；加载中保留旧封面。
- 图标：复用 public/previous|play|pause|next.png（黑色模板字形），按注册表 SystemUsesLightTheme 染白/保黑，WM_SETTINGCHANGE 重建。
- 线程模型：Win32/COM 全在窗口线程（SetWindowSubclass，UI::Shell 模块不是 Controls）；其它线程改共享态后 SendMessageW(WM_APP_TASKBAR_REFRESH)。

踩点：windows crate 0.61 里结构体是 THUMBBUTTON（非 THUMBNAILBUTTON）、字段 CamelCase（dwMask/iId/…）；CreateBitmap 直接返回 HBITMAP 不是 Result；SendMessageW 参数是 Option<WPARAM/LPARAM>；CoCreateInstance 的 punkouter 要 `None::<&windows::core::IUnknown>`；BI_COMPRESSION(.0)。mac 上可用 `cargo check --target x86_64-pc-windows-msvc` 做 Win32 代码类型检查（rustup target add 即可，无需 MSVC 链接）。
