## mini → 全屏「背景色闪一下 / 重新下大封面」修复（mobile + hm）

- 根因（两端同构）：取色**只在全屏页挂载时**触发（`useCoverVisual` 唯一调用点 player.tsx / hm `refreshCoverColor` 仅在 PlayerPage），mini 态 `dominantColor` 内存 Map 是空的 → 首帧 coverColor=null 退中性黑，异步「下载 96px PNG → 解码取色」回来才跳成主题色；且 mini 用 96 档、全屏用 900/600 档 + 背景 300 档，URL 不同导致图片缓存不命中，进全屏重新下载大图。
- 方案：曲目一确定就在全局层闲时预热（mobile `PlayerProvider` / hm `PlayerStore.notify`），**两档时机**——主题色立即起步（决定闪不闪，不能等闲时），大封面延迟 3s（对齐项目既有 `triggerCacheWhilePlaying` / `setTimeout(3000)` 的「让音频先缓冲」范式）。放全局层而非 MiniPlayer 组件：覆盖冷启动恢复、车机 embedded、播放流转等全部入口。
- **mobile**（3 文件）
  - 新增 `src/utils/playerVisualPrefetch.ts`：`fetchCoverVisual()` 填主题色 + 本地磨砂图（data URI）缓存，`useCoverVisual` 首帧同步读；闲时 `Image.prefetch` 900/300 档。带 mediaHeaders 或外链封面跳过 prefetch（不支持 headers；外链 `getImageUrl` 直返原 URL、与尺寸无关，mini 已加载过）。
  - `src/context/PlayerContext.tsx` 挂 `useEffect([currentTrack?.cover])`（按 cover 而非 track 对象，飞牛歌词并回 currentTrack 不重复调度）。
  - `src/utils/dominantColor.ts` 加 `invalidateCoverVisual()`。
- **hm**（5 文件）
  - 新增 `utils/coverCache.ets`：通用封面落盘缓存。落盘路径复用 `fileCache.coverPath(url, 'jpg')`，与 `fnosCover.resolveFnosCover` **同一个文件**互相命中；飞牛源委托 `resolveFnosCover` 共用 inflight（避免两个任务并发 TRUNC 写同一文件）。导出同步索引 `getCachedCoverUri/coverDisplayUri`、`hydrateCachedCoverUri`（冷启动只查磁盘不下载）、`prefetchCoverToDisk`。

## 修复：播放详情页设备流转总是失败 + Android mobile 不出现在其它端设备列表

### 排查结论（实测，非猜测）
- 用 socket.io-client 直连运行中的 `127.0.0.1:3000`，模拟两台设备 A/B 发 `transfer_session`：
  B 收到 `transfer_received`、A 收到 `transfer_sent` → **服务端 gateway 的匹配/ack 逻辑本身完全正常**。
- 只读查 `dev.db` 的 Device 表：所有设备 `isOnline=0`、`lastSeen` 都是旧时间 → 各端 WS 根本没注册成功，
  端侧过滤条件 `d.isOnline && d.deviceId` 自然把设备全部滤掉，流转必然 `device_offline`。
- ⚠️ 历史坑（2026-09-15 日志）：web/hm 曾连 NAS `192.168.1.6:8865`，本机 3000 是另一套库。
  **多端必须连同一台服务端**，否则设备互不可见（配置问题，代码修不了）。

### 确定的代码根因
1. `apps/desktop/vite.config.ts` 只代理 `/api`，**没代理 `/socket.io`**。desktop web dev 的
   `socket.ts` 用 `window.location.origin`(5173) → socket.io 握手落到 Vite SPA fallback → WS 永不连接。
   target 还写 `localhost:3000`，macOS 优先解析 ::1 而后端只听 IPv4 → 实测 502 Connection refused。
2. `apps/mobile/src/services/socket.ts` 直接读 `AsyncStorage("serverAddress")`，与 HTTP 的
   `getBaseURL()`（经 autoSwitchServer 归一化）可能不一致；带路径的地址（`/api`、`http://x/api`）
   会被 socket.io-client **当成 namespace** → 连到不存在的 namespace → Android 注册不上。
3. `SharedSocketService.connect` 业务参数只放 query 不放 auth；`if (this.socket?.connected) return`
   导致切源/换账号不重连；重复 connect 会销毁刚发起的握手。
4. `userService.setDeviceOffline` 的 name 兜底**不带 platform**（saveDevice 带了）→ 同名不同端
   断开时互相误置离线，设备从列表莫名消失。
5. 后端 `POST /user/devices/transfer`（REST 转发）早已存在、`@soundx/services` 也导出了
   `transferSession()`，但 desktop/mobile 的 `handleTransferToDevice` 只走 WS，WS 一断直接弹失败。
