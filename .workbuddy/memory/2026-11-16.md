# 2026-11-16

## 修复：播放详情页设备流转总是失败 + Android mobile 不出现在其它端设备列表

### 排查结论（实测，非猜测）
- 用 socket.io-client 直连运行中的 `127.0.0.1:3000`，模拟两台设备 A/B 发 `transfer_session`：
  B 收到 `transfer_received`、A 收到 `transfer_sent` → **服务端 gateway 的匹配/ack 逻辑本身完全正常**。
- 只读查 `dev.db` 的 Device 表：所有设备 `isOnline=0`、`lastSeen` 都是旧时间 → 各端 WS 根本没注册成功，
  端侧过滤条件 `d.isOnline && d.deviceId` 自然把设备全部滤掉，流转必然 `device_offline`。
- ⚠️ 历史坑（2026-09-15 日志）：web/hm 曾连 NAS `192.168.1.6:8865`，本机 3000 是另一套库。
  **多端必须连同一台服务端**，否则设备互不可见（配置问题，代码修不了）。

### 确定的代码根因
1. `apps/desktop/vite.config.ts` 只代理 `/api`，**没代理 `/socket.io`**。desktop web dev 的
   `socket.ts` 用 `window.location.origin`(5173) → socket.io 握手落到 Vite SPA fallback → WS 永不连接。
   target 还写 `localhost:3000`，macOS 优先解析 ::1 而后端只听 IPv4 → 实测 502 Connection refused。
2. `apps/mobile/src/services/socket.ts` 直接读 `AsyncStorage("serverAddress")`，与 HTTP 的
   `getBaseURL()`（经 autoSwitchServer 归一化）可能不一致；带路径的地址（`/api`、`http://x/api`）
   会被 socket.io-client **当成 namespace** → 连到不存在的 namespace → Android 注册不上。
3. `SharedSocketService.connect` 业务参数只放 query 不放 auth；`if (this.socket?.connected) return`
   导致切源/换账号不重连；重复 connect 会销毁刚发起的握手。
4. `userService.setDeviceOffline` 的 name 兜底**不带 platform**（saveDevice 带了）→ 同名不同端
   断开时互相误置离线，设备从列表莫名消失。
5. 后端 `POST /user/devices/transfer`（REST 转发）早已存在、`@soundx/services` 也导出了
   `transferSession()`，但 desktop/mobile 的 `handleTransferToDevice` 只走 WS，WS 一断直接弹失败。

### 改动（10 个文件，含 MEMORY.md 压缩重写）
| 文件 | 改动 |
|---|---|
| `apps/desktop/vite.config.ts` | 补 `/socket.io` 代理（`ws:true`）；`/api`、`/socket.io` target 改 `127.0.0.1:3000` |
| `packages/ws/src/index.ts` | 新增 `normalizeSocketUrl()`（纯字符串解析，剥路径防 namespace 误解析，RN 的 URL 存根安全）；auth 双通道带 deviceName/deviceId/platform/userId；显式重连配置；按 `url\|token\|userId\|deviceId` signature 判断是否重连，参数未变时绝不重建 socket；`ensureConnected()` |
| `apps/mobile/src/services/socket.ts` | 改用 `getBaseURL()` 与 HTTP 同源；去掉 connected 早退；AppState 回前台重新 connectWithContext（Android 后台冻结定时器）；override disconnect 清凭据 |
| `apps/desktop/src/services/socket.ts` | 去掉 connected 早退，交给共享层判断重连 |
| `services/api/src/services/user.ts` | `setDeviceOffline` name 兜底补 platform |
| `services/api/src/gateways/sync.gateway.ts` | 目标 WS 离线时**暂存流转**（内存 Map，TTL 10min）→ 回 `transfer_sent(queued:true)`，设备上线 `handleConnection` 时补投（deviceId 漂移按 name+platform 兜底）；REST `forwardTransfer` 同名兜底 + 暂存；handleDisconnect 传 platform |
| `services/api/src/controllers/user.ts` | transfer body 补 `targetDeviceName/targetPlatform` |
| `apps/desktop/src/components/Player/index.tsx`、`apps/mobile/app/player.tsx` | ack 改三态 `sent/failed/timeout`；WS 未连接 / 明确失败时走 REST `transferSession()` 兜底；timeout 不重发（避免目标端重复起播）；`queued` 打日志 |
