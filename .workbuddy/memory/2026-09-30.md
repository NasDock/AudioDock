## 修复：hm 沉浸式最终方案（全屏 + 避让区 padding）

- 第一版只开 setWindowLayoutFullScreen，导致所有页面内容从物理 y=0 排版被状态栏盖住。
- 关键认知（官方文档）：expandSafeArea **不改变布局**，只扩展绘制区域；全屏后必须自己做避让 padding。
- 最终方案：
  1. `services/systemBar.ets` setSystemBarWindow：开全屏 + getWindowAvoidArea(TYPE_SYSTEM/NAVIGATION_INDICATOR) 换 vp 存 AppStorage('statusBarHeightVp'/'navBarHeightVp')，并监听 avoidAreaChange 动态刷新。
  2. RootShellPage：Navigation 加 `padding({top: statusBarHeightVp, bottom: navBarHeightVp})`（一次覆盖所有 tab + NavDestination 页面）；NavDestination 上的 expandSafeArea 全部移除（会带内容渗出）。
  3. GlobalBottomBar：根容器加 `padding({bottom: navBarHeightVp})`，替代 expandSafeArea。
  4. 21 个独立 @Entry 页面：统一加两个 @StorageProp + 根容器 padding（LocalizedContent 页用 Column 包裹；ArtistDetail/Scan/SectionOrder/SourceManage/Index 直接在现有根容器追加）。
- 坑：SettingsPage/MiSpeakerPage 文件里有两个 struct，@StorageProp 要加在 @Entry 页面 struct（文件后部），不是前面的子组件 struct。
- hvigor 构建通过，已跑 harmony-cleanup。
