## 合并后流水线双失败修复

### Docker：ERR_PNPM_LOCKFILE_CONFIG_MISMATCH（overrides 不匹配）

- 根因：合并提交 88a854c1 把 **未解决的 git 冲突标记**（`<<<<<<< HEAD`/`=======`/`>>>>>>> origin/master`）提交进了 pnpm-lock.yaml（411-415 行，react-native-carplay 的 patch_hash 版本行）。pnpm 读到标记会 "Merge conflict detected ... successfully merged" 自动合并，但合并结果丢了 overrides 一致性 → frozen 安装必挂。
- 修复：手动解冲突保留带 `patch_hash=8af880b5...` 的 HEAD 侧，本地 `pnpm install --frozen-lockfile` 验证通过。
- 教训：**合并后提交前务必 `grep -rn "^<<<<<<<" pnpm-lock.yaml` 检查冲突标记**；lockfile 冲突建议直接删标记后跑 `pnpm install --no-frozen-lockfile` 让 pnpm 重建。

### Android：NDK 27.1.12297006 安装失败（Error on ZipFile unknown archive）

- 根因：RN 0.81 默认 ndkVersion=27.1.12297006（rootProject.ext 由 RN gradle 插件注入，不在项目 build.gradle 里）。ubuntu-latest 镜像不预装该版本时 gradle 自动下载安装，无校验无重试，zip 损坏直接挂。
- 修复：feat-test-release.yml + android-release.yml 在 Verify Android SDK 后加 "Install NDK 27.1.12297006" 步骤：已装则跳过，`sdkmanager "ndk;27.1.12297006"` 带 3 次重试（失败后删残目录 sleep 10 再试），最后 `ls` 校验目录存在。
- 追加坑：**GitHub ubuntu runner 的 sdkmanager 不在 PATH**（Verify 步骤的 `sdkmanager --version || true` 一直静默失败没暴露）。真实路径 `$ANDROID_HOME/cmdline-tools/<版本>/bin/sdkmanager`，需 `ls -d .../cmdline-tools/*/bin/sdkmanager | sort -V | tail -1` 动态定位（兜底 tools/bin/sdkmanager）。

## 播放详情页滚动条修复（transform 计入 scrollable overflow）
- 现象：加封面背景后 Drawer 出现横竖滚动条。
- 根因：fullPlayerBgImage 的 transform: scale(1.2) **会扩大祖先的 scrollable overflow 区域**（transform 不影响布局但影响滚动溢出），antd Drawer body 默认 overflow:auto 且可能压过模块 CSS 的 overflow:hidden → 放大 20% 的背景撑出滚动条。
- 修复：模糊图外包 .fullPlayerBg（absolute inset:0 + overflow:hidden）裁剪容器；.fullPlayerBody 的 overflow:hidden 加 !important 保底。
- 教训：**绝对定位装饰层带 transform 时，必须套 overflow:hidden 裁剪容器**，不能依赖 scroll container 自身的 overflow。

## 歌词滚动垂直不居中修复
- 根因：Lyrics.tsx 自动滚动用 line.offsetTop，但 .lyricsContainer/.lyricsContent 都无定位，offsetTop 锚到 .fullPlayerContent（有 position:relative），中间隔着标题/艺术家区块 ~100px → active 行恒偏上。
- 修复：改用 getBoundingClientRect 换算（lineRect.top - containerRect.top + container.scrollTop），免疫 offsetParent 层级。CarMode 同用该组件一并受益。
- 教训：滚动定位别用 offsetTop（依赖 offsetParent 链），一律 rect 差值 + scrollTop。

## 播放详情页封面/歌词背景竖线色差修复
- 根因：.fullPlayerRight 带 backdrop-filter: blur(20px)，左侧封面区直出背景、右侧隔着一层 backdrop blur 看同一背景（blur 非幂等，80px+20px≈82px 且 GPU 取色有舍入差）→ 交界处竖线。
- 修复：删掉该 backdrop-filter（背景本身已是模糊封面，无需再糊）。教训：**同一视觉背景被「直出区」和「backdrop-filter 区」拼接时必有色差**，背景层统一放底层、内容区不要再加 backdrop-filter。
