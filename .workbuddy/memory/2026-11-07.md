## mobile 封面主题色「本地解析兜底」（纯 JS，可 OTA）
- 需求：mobile 端能否本地解析封面主题色。方案选定**兜底模式**：服务端 `/image/dominant-color` 优先，失败/外链才本地算，避免正常场景精度回退。
- 实测数据（60 张真实封面 vs desktop canvas 300→32 算法）：
  | 本地取样 | 平均 Δ | 最差 Δ | >8 的张数 | 体积 |
  |---|---|---|---|---|
  | 96px JPEG | 3.93 | **83** | 4 | 2.0KB |
  | 192px JPEG | 2.18 | 18 | 3 | 6.0KB |
  | **96px PNG** | **1.68** | **11** | 1 | 18KB |
  | 300px PNG | 1.83 | 12 | 3 | 143KB |
- 关键结论：**精度取决于缩放路径而非图片尺寸**（192/300 比 96 差，因为两次插值；96=32×3 块平均是精确降采样）。JPEG 的 Δ83 灾难样本（`谢春花 - 荒岛`）是"大面积浅底+小面积彩色"被压缩抹平，阈值过滤后无一像素通过 → 退化全图平均变白。**必须用 PNG**。
- 实现：
  - `src/utils/dominantColorLocal.ts`：`expo-file-system/legacy.downloadAsync` → base64（自写解码器，无第 3 个依赖）→ 魔数判 PNG/JPEG → `upng-js` / `jpeg-js` 解码 → 32×32 分块平均 → desktop 同源阈值算法（跳过 max<40 / min>215 / max-min<20，全过滤则整体平均）。
  - AudioDock 源请求 `/image/optimize?w=96&fmt=png`（18KB）；外链封面直接取原图，`>3MB` 放弃解码。
  - `dominantColor.ts` 改为两级：`fetchServerColor`（仅 /covers/）→ 失败则 `resolveLocalDominantColor`。内存 cache/inflight 沿用。
  - `src/types/image-decoders.d.ts` 补 jpeg-js / upng-js 模块声明（都无官方类型）。
- 依赖：`jpeg-js@0.4.4`（decoder 不依赖 Node Buffer）、`upng-js@2.1.0`（依赖 pako）。**均纯 JS，不需要重打 APK，可走 OTA**。
- 坑：`upng-js` decode 出的 `data` 带 filter byte（96×96 → 27744），必须走 `toRGBA8()[0]`；`jpeg-js` decode 需 `{ useTArray: true }` 才返回 Uint8Array。
- 遗留：外链封面的磨砂底图仍缺（`getBlurredCoverUrl` 只认 /covers/，服务端 optimize 白名单不含外链域），目前外链只有渐变+黑罩，无磨砂。

## mobile 播放页兜底取色与磨砂背景修复
- 根因：服务端 `/image/optimize` 当时只放行 `fmt=webp/jpeg`，mobile 本地兜底首选请求 `fmt=png` 会 400；原实现没检查 `downloadAsync` HTTP status，继续把错误页当图片解码 → 返回 null，播放页退成黑色渐变；外链封面也没有磨砂底图。
- 修复：
  - 服务端 `OutputFormat` 增加 `png`（sharp PNG 输出、缓存扩展名/Content-Type、quality cache key 归一为 0）。
  - mobile 本地兜底候选链：96px PNG（新服务端）→ 原图（兼容老服务端，≤8MB/3MP）→ 96px JPEG（webp/过大原图兜底）；检查 HTTP status，单候选 10s 超时，服务端 dominant-color 8s race 超时。
  - 本地解码后用 desktop 同源 32×32 阈值平均取色（跳过 max<40 / min>215 / max-min<20，全过滤整体平均），并生成 96px 近似高斯模糊 PNG data URI 作磨砂底图。
  - `useCoverVisual` 同步读内存缓存；`resolved` 门控避免旧服务端先闪清晰原图再切磨砂；缓存 100 条上限、inflight 异常兜底。
- 验证：API tsc/build 通过；直接实例化 `ImageOptimizeService` 验证 PNG 输出与 dominant-color 成功；mobile Android `expo export` 通过；mobile 全量 tsc 仍有既有错误（artist/member-benefits/webdav-sources/SkeletonBlock/networkUtils），无本次修改文件错误。

## mobile 播放页本地取色 + 关闭动画落点修复
- 主题色策略调整：mobile 播放详情页不再请求服务端 `/image/dominant-color`，`fetchCoverVisual` 恒走 `resolveLocalCoverVisual` 本地解码计算；AudioDock 源仍按 96px PNG → 原图 → 96px JPEG 获取像素，外链取原图，阈值算法保持 desktop 同源。磨砂图与主题色同源，优先使用本地生成 data URI。
- 关闭动画根因：`_layout.tsx` 之前把恢复中的 `GlobalBottomBar` 做成 absolute 浮层，React Native Screens 的 native 转场层级不受普通 JS zIndex 完全控制，Android 上底部栏会盖住正在下滑的播放页，表现为页面到 mini 播放器顶部就消失。
- 修复：播放页退场期间（仅 player → 非全屏路由）保持 `GlobalBottomBar` 卸载，`Stack` 维持全屏让页面完整滑到底；`transitionEnd` 精确恢复，1.5s 兜底；移除 `GlobalBottomBar.floating`。
- 验证：Android `expo export` 通过；修改文件 ESLint 0 errors（`_layout.tsx`/`player.tsx` 仍有既有 warnings）；mobile 全量 tsc 仍只有既有错误，改动文件无新增错误。

## mobile 播放页关闭后的底部栏恢复动画
- 问题：上一版修复让播放页完整滑到底，但 `transitionEnd` 后 `GlobalBottomBar` 立刻回到文档流，Stack 瞬间被压缩一个底部栏高度，视觉上底层页面被向上顶一下。
- 修复：离开 player 时记录 `bottomBarAnimateIn`；退场结束后挂载 `GlobalBottomBar`，外层高度 240ms 从 0 展开到 `MINI_PLAYER_HEIGHT + 49 + insets.bottom`，内容 absolute 锚定底部并渐显，实现「从底部平滑露出」，底层内容同步压缩。
- `MINI_PLAYER_HEIGHT=60` 从 MiniPlayer 导出共用，避免高度硬编码漂移；进入任意全屏路由会重置未完成的恢复动画，防连续导航残留。
- 验证：Android `expo export` 通过；动画相关文件 ESLint 0 errors（`_layout.tsx` 既有 import/hooks warnings）；全量 tsc 仍只有既有错误。

## mobile 播放页进入动画起点修复（覆盖式底部栏）
- 问题：上一版底部栏回到文档流，进入 player 时 bar 卸载导致根 Stack 高度从「屏幕高 - bar」变全屏；native `slide_from_bottom` 以容器 frame 计算起点，变成从 mini 播放器顶部开始。
- 修复：`GlobalBottomBar` 改为 absolute 覆盖式；根 Stack 恒全屏，普通页面通过 `screenOptions.contentStyle.paddingBottom` 预留 `MINI_PLAYER_HEIGHT + TAB_BAR_BASE_HEIGHT + safeAreaInsets.bottom`。player screen 显式 `paddingBottom: 0`，player 显示期间底层 tab 保留 padding，避免进入/退出转场中布局变化。
- 退出行为保持：播放页退场期间底部栏卸载，结束后再从底部高度展开恢复。
- 验证：Android `expo export` 通过；修改文件 ESLint 0 errors；全量 tsc 仍只有既有错误。

## mobile 播放页进入仍从 mini 顶部开始的层级修正
- 真机反馈覆盖式底部栏后进入仍像从 mini 顶部开始。保留「根 Stack 恒全屏 + contentStyle 只为普通页面内容预留空间 + player paddingBottom=0」结构，不压缩 player frame。
- 追加修正：`GlobalBottomBar` 普通状态保持 zIndex/elevation 10，player 进出场或退场恢复 pending 时传 `layerBelow`，压到 native screen 下层；这样即使转场首帧还有旧底部栏，也不会遮挡 player，进入/退出都按屏幕真实底部起止。
- `(tabs)/_layout` 不做额外 inset，所有普通 root screen 统一由根 Stack contentStyle 预留，避免详情页被覆盖。
- 验证：Android `expo export` 通过；修改文件 ESLint 0 errors（既有 warnings）；全量 tsc 仍只有既有错误。

## mobile 播放页转场改为 JS 自驱动（绕开 native 起点问题）
- 真机多轮验证：无论覆盖式底部栏还是 layerBelow，进入仍从 mini 顶部开始，说明 React Navigation native `slide_from_bottom` 的起点不可控。
- 最终方案：`/player` screen 改 `presentation: "transparentModal"`、`animation: "none"`、`gestureEnabled: false`、`contentStyle: { paddingBottom: 0, backgroundColor: "transparent" }`；`PlayerDetailView` 内用 `Animated.Value` 自驱动进入 `height → 0`、关闭 `0 → height` 完成后再 `router.back/replace`。
- 所有顶层返回分支（无 track/横屏/竖屏）统一包 `renderWithTransition`；embedded 车机面板不动画；关闭前 `stopAnimation` 防快速进出竞态。
- 效果：进入/离开都严格按 `useWindowDimensions().height` 起止，滑动时透明 Modal 下方仍是上一页，不再被 mini 播放器/Tab 截断。
- 验证：Android `expo export` 通过；修改文件 ESLint 0 errors（既有 warnings）；全量 tsc 仍只有既有错误。
